# BOSS 附件两阶段识别

## 采集范围

插件只读取当前可见附件中的 `.bzl-office-pdf .textLayer`，并递归检查可见的同源 iframe。文字从 DOM 文本节点取得，按 PDF 页和位置整理；AI 识别请求只上传纯文本，没有 HTML、样式、图片、Cookie 或附件下载令牌。不读取 Vue 对象，也不改变招聘页面的业务 DOM。

图片型 PDF 没有可用文字层时会提示无法读取，不会偷偷改用 OCR。附件文字稳定后自动识别基础资料，无须勾选或点击；能确认缺页或存在尚未载入的文字层时继续等待。网页未提供可信总页数时，只能识别已加载的文字，不把已挂载页数冒充完整总页数。

## 两次识别

1. 基础识别：只返回姓名、完整手机号、原文明示的性别，以及开始时间最早的一段工作公司和学校及起止时间。只有年份就保留年份，不补月份，不按姓名猜性别。只标为微信的纯数字号码不自动当手机号，手机受到平台保护时保持空白。
2. 用户点击添加或更新时，才进行完整简历解析。完整 JSON 合同与现有批量简历导入保持一致；结果仍通过已有候选人新增或版本化更新接口保存，收藏夹、备注和岗位推荐继续沿用原流程。

用户手动修改过的字段优先。切换候选人或账号后，旧结果不会填入新页面。完整解析返回后再次查重，避免只凭第一阶段信息重复建档。

## 服务器接口

- `POST /api/candidates/attachment-parses`：创建 `basic` 或 `full` 任务，提交纯文本、请求编号、当前附件编号和内容摘要。
- `GET /api/candidates/attachment-parses/{id}`：读取同一账号的任务。
- `POST /api/candidates/attachment-parses/{id}/cancel`：取消任务。

接口只接受插件专用会话。服务器按登录用户读取 AI 配置；未配置时返回 `AI_NOT_CONFIGURED`，不会使用系统默认账号代替。内置 AI 继续经过原有余额和用量计费入口；外部 AI 使用本人配置。

调用前先保存幂等回执。网络中断时恢复或查询原任务，不自动重新付费请求。取消、超时或结果不明会明确提示可能已计费。服务器任务回执包含已识别的结构化字段，最多保存七天用于恢复；不保存附件原文或 AI Key。

完整结果中只有出生年份时，不给现有 `birth_ym` 字段编造月份，明确年份保留在 `basic_info`；工作和学校日期可以保留原文年份。AI 需要支持现有批量导入所用的 OpenAI 兼容请求合同；接口地址必须是服务器可访问的公网 HTTPS。

## 系统提示词

基础识别提示词位于“系统配置 → AI 配置 → AI 默认提示词 → BOSS 附件基础识别提示词”，复用现有 `ai.default_prompts` JSON，字段为 `boss_attachment_basic_prompt`。新识别读取最新配置；旧配置未含字段时使用安全默认值，无须数据库迁移。恢复旧请求仍沿用原回执，不会因管理员改提示词而重复调用 AI。

## 附件头像

仅检查当前唯一附件容器中的独立 `img` 或 SVG `image` 地址，按尺寸和比例保守筛选。明显图标、Logo、二维码、横幅和整页预览会排除，多个候选无法确定时留空。没有独立图片地址时跳过，不读取平台隐藏数据，也不从 PDF 画布猜测裁脸。

可用头像沿用插件现有后台下载、解码和缩图流程，在用户点击保存时处理，不新增服务器图片代理，不向基础识别 AI 发送图片。

## 验收要求

- 合成测试覆盖同源 iframe、隐藏或跨源附件、嵌套文字不重复、多页不完整、HTML 去除、两阶段调用、人工修改、切人切号、无 AI 配置及重复请求。
- 后端使用模拟 AI 验证结构化字段和调用次数；不把真实简历放进测试文件、日志或邮件。
- 当前真实 Firefox 附件已验证同源 iframe 路径 `/bzl-office/pdf-viewer-b` 和可读取的文字层；该证据只证明所测附件，不保证所有附件都有文字层。
- Firefox 正式分发必须使用 Mozilla 签名包；未签名测试包不能替换公开的正式 Firefox 下载配置。

## Firefox 网站权限

旧版升级后，新增的 BOSS 网站权限可能尚未开启。请在 Firefox 的扩展管理中打开 GoodHR 简历助手，进入“权限与数据”，允许访问 `www.zhipin.com`，再刷新 BOSS 页面。未授予该权限时，插件不会读取 BOSS 附件，也不会显示附件浮窗；这与是否登录 GoodHR 无关。
