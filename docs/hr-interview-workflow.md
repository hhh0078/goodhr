# 企业 HR 招聘流程（第一期）

入口在后台「招聘管理」中的「企业招聘」和「招聘设置」。简历详情也有「企业招聘流程」区域，可为该候选人选择岗位并启动流程。

## 如何开始

1. 团队管理员在「招聘设置 → 公司信息」填写公司名称、招聘联系人和联系邮箱；电话、公司地址按邮件内容需要填写。
2. 团队自带「简历初筛 → 面试 → 录用审核 → Offer → 入职确认」流程。管理员可新建、复制、修改多套流程，增加或调整节点，并选择默认流程。
3. 每个节点可设置负责人、面试官、审核人、内部抄送人，以及「全部审核人通过」或「任一审核人通过」。人员只能选择已加入当前团队的成员。
4. 从简历详情或企业招聘页选择候选人、岗位及流程，人工启动招聘。同一候选人同一岗位最多有一条进行中的流程；结束后可以重新启动。
5. 在面试节点安排面试，选择时间、时长、团队面试官和现场/视频/电话方式。保存安排后，预览邮件，再明确发送。

现有猎头推荐、岗位跟进、简历备注和自动任务记录继续保留。已有推荐阶段不会自动转换成新的 HR 流程。

## 节点与任务规则

- 流程实例保留启动时的模板版本。后续编辑模板不改变已经启动的流程。
- 团队管理员、招聘负责人和当前节点负责人处理排期、推进、退回、终止；审核人和面试官只能提交指定的审核或面评。
- 一轮面试可以安排多场。需要面评的节点，必须完成有效场次并收齐每位指定面试官的评价，才能推进；配置了审核人时，也必须达到该节点的审核要求。
- 面试评价、候选人确认参加、实际面试完成分别记录。面试还没开始时不能登记完成或提交面评。
- 退回节点会开始新轮次，旧轮次的面评和审核不会直接满足新轮次。历史记录保留。
- 当前及后续节点可以重新分配人员；已排场次可以转交给有效团队面试官，并保留原评价。排期修改、取消、转交、流程结束后，旧版本确认链接失效。
- 「我的待办与抄送」列出本人待处理任务和未读进度。内部抄送是系统内通知，不会把内部意见发送给候选人。
- 多人同时操作使用版本校验；旧页面不能覆盖同事刚更新的进度，需刷新后继续。
- 入职确认需登记实际入职日期，日期未到不能确认完成。

## 邮件模板与发送

团队初始化七类邮件：初试、复试、改期、取消、结果、Offer、入职。预置模板可以编辑或删除，也可以复制、新建自定义模板。

占位符使用中文花括号，如 `{简历姓名}`、`{岗位名称}`、`{当前时间}`、`{公司名称}`、`{招聘联系人}`、`{联系邮箱}`、`{面试时间}`、`{确认链接}`、`{入职日期}`。编辑器提供完整目录、插入按钮和示例预览；实际发送前再次读取候选人和当前安排，提供真实预览。时间以北京时间显示。

- 未知变量、缺失变量、未替换的预置待填提示、无效收件邮箱或必要公司信息，会阻止发送。Offer 条件、结果说明和报到材料需由 HR 编辑为已确认内容。
- 邮件标题统一添加 `[公司名称]` 前缀。第一期使用平台已配置的 SMTP 邮箱；候选人回复通过 Reply-To 交给团队联系邮箱。公司自己的 SMTP 配置留待后续。
- 没有配置平台 SMTP 时只能预览，不会记录成发送成功。
- 同一次点击和网络重试复用发送编号。邮件服务是否接收不确定时，保留记录并阻止自动重发；需要先人工核实。
- 发送记录保存当时的收件人、回复邮箱、标题、正文、流程和场次版本。以后修改模板或公司信息不会改变历史邮件。
- 新邮件使用简历当前邮箱。删除简历后招聘与邮件历史仍保留，但不会继续向旧邮箱发送新邮件。
- 候选人通过邮件中的受限链接确认参加、申请改期或拒绝。申请改期只是告知 HR，不能自行更改排期；公开页面只展示该场面试安排，不展示内部面评、审核、成员邮箱或完整简历。

## 维护与验收

云端接口统一使用 `/api/recruitment/`；受限邀请使用 `/api/public/recruitment/invitations/{token}`，前端确认页面为 `/interview-invitation/{token}`。邀请令牌数据库只保存 SHA256 哈希。

数据库迁移为 `0090_recruitment_workflows.sql` 和 `0091_recruitment_mail.sql`，全部表与字段有中文备注。生产使用已有 PostgreSQL 连接；本地无数据库模式用于开发，数据仅在进程内保存。

验收覆盖后端完整测试、独立本机 PostgreSQL 持久化及并发测试、前端类型检查/构建、新招聘流程 UI 回归，以及原简历库 UI 回归。邮件传输使用假发信器测试，不向真实候选人发送测试邮件。本次开发不包含线上部署。
