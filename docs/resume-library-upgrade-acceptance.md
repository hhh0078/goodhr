## 已实现

| 区域 | 交付行为 |
| --- | --- |
| 简历列表 | 移除旧标题、说明和清空按钮；左侧紧凑搜索及更多筛选，右侧下载插件与添加；查询和分页写入 URL |
| 添加、编辑 | AI 批量解析、手动添加；姓名与有效手机号必填；精确、模糊查重；比较更新和版本校验；手动编辑可逐字段勾选明确清空，默认保留；AI、插件空值不覆盖原内容 |
| 资料与来源 | 复用原简历主体，补年龄、性别、地区、标签、状态、薪资原文、多平台来源；小数薪资单位 K；旧空手机号、重复记录保留 |
| 备注、推荐 | 独立追加备注；多岗位人工关联、推荐阶段及历史；失败只重试未成功步骤；岗位卡片可进入该岗位候选人 |
| AI 导入 | 本地 PDF、DOCX、TXT、PNG/JPEG；扫描 PDF 交给本地 OCR；SQLite 草稿、账号隔离、取消及重启恢复；未知计费结果不自动重做 |
| 插件 | Chrome、Firefox 共用 1.0.0；猎聘企业端独立详情/聊天弹框、猎聘猎头、智联、前程无忧读取适配；未登录本地预览、补手机、查重、备注、岗位及历史 |
| 登录 | 邮箱密码、验证码；首次控制台确认本地配对后可恢复；独立受限插件凭证；切号隔离、原子续期/退出、撤销本地恢复授权 |
| 下载 | 简历库入口与官网 `/download#browser-extension`；超级管理员通过 `system.browser_extension` 维护统一版本、两种 URL、SHA256 与 Firefox 签名状态 |

插件内容脚本只读取可见 DOM。表单在插件弹窗/侧栏，不插入招聘页面浮层，不点击、滚动、解锁、购买、不读取平台 Cookie 或内部缓存。原 Go Agent → Worker 自动化链路继续保持零 JS 注入。

## 真实采集验收

1. 在猎聘企业端独立简历页打开用户指定候选人，再在 `/chat/im#preview` 打开同一个候选人的详情弹框；分别点击 GoodHR 图标。无需登录插件即可查看本地读取结果。
2. 检查姓名、完整手机号、城市、年龄、学历、职位、期望、工作/教育经历；页面未展示的值应留空，不猜号码。参数 `resIdEncode` 用于平台身份，保存的来源 URL 去除查询参数。
3. 切换候选人、关闭弹框，确认旧人的备注和岗位选择不混到新人；隐藏详情不能被采集。暂不支持第三方 iframe 内详情，多人同时可见时不猜测。
4. 其他平台按相同步骤分别验收；当前没有这些真实账号验收证据。
5. 先只看读取结果。使用云端新增、查重、登录、备注和推荐前，必须先更新配套后端、迁移和前端。当前线上旧接口登录返回 404，插件会提示先使用本地预览；这不代表手机号读取失败。

浏览器工具安全策略不允许进入 `chrome://extensions`，且当前招聘页 DOM 调试上下文不可用。本轮只通过可见页面确认目标简历存在，没有绕过限制，也没有把真实简历写入测试样本、仓库或云端。
