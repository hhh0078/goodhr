## 2. 需求理解与建议结论

把简历库从自动任务结果列表，升级为可日常维护的候选人库：能手动新增、批量解析、插件采集、查重、写多条备注、关联岗位并查看推荐历史。

保留 GoodHR 现有简历主体和岗位，不另建一套简历库或岗位。参考 Hi Match 的列表密度、简历详情结构、独立备注和候选人与岗位多对多关系；沿用 GoodHR 的组件、主题和权限。

新入口统一要求有效手机号后才正式入库；未识别到手机号时保留待确认草稿，提示手动补充。旧简历和既有自动任务仍允许手机号为空，避免本次改造导致招聘任务中断。

本次“岗位推荐”指记录人工选择、推荐和跟进，不自动向招聘平台、客户或候选人发消息，也不因选中岗位就启动招聘任务。

## 4. 简历库界面

### 4.1 顶部查询和添加

按用户要求移除表格上方现有大标题、默认不生成简历说明、清空简历库按钮及旧查询布局。移除入口不执行清空数据。

新布局：

```text
左：关键词 | 手机号 | 岗位 | 来源 | 查询 | 重置 | 更多筛选    右：＋添加
更多筛选：地区、学历、工作年限、求职状态、标签、入库人、入库时间
─────────────────────────────────────────────────────────────────
候选人 | 最近经历 | 求职意向 | 岗位/推荐 | 最新备注 | 来源/入库 | 操作
─────────────────────────────────────────────────────────────────
共 X 份简历                                      分页、每页数量
```

- 关键词覆盖姓名、公司、职位、学校和简历正文；手机号支持完整号码和片段检索。
- 常用筛选一行优先，窄屏自然换行；更多条件折叠。岗位下拉支持搜索和分页，显示所有有权限访问的岗位，不固定只取前 20 个。
- 查询条件和分页写入 URL，返回列表保留搜索；输入后按回车查询，重置恢复第一页。
- 使用 Ant Design Table、AdminDialog、ChoiceCards；主题使用现有 `--goodhr-*` 变量，不写死颜色，不使用蓝紫渐变。
- 空状态保留“添加”入口，短文案示例：“这里暂时空空的，先加一份简历，我来认真记账。”

### 4.2 表格内容

| 列 | 展示内容 |
| --- | --- |
| 候选人 | 姓名为主，手机号、年龄/学历/工作年限为辅助；姓名点击详情 |
| 最近经历 | 最近 1–2 段公司、职位和起止年月，长内容省略 |
| 求职意向 | 期望职位、地区、薪资、求职状态 |
| 岗位/推荐 | 关联岗位、推荐数量与最新阶段；点击看完整记录 |
| 最新备注 | 最近一条的内容摘要、操作人和时间；点击看全部备注 |
| 来源/入库 | 来源标签、入库人、入库时间，多平台来源可查看 |
| 操作 | 编辑、加备注、推荐到岗位，更多操作收起 |

AI 分析从固定宽列移入详情，列表可显示简短评分提示；人工录入而未分析的简历显示“未分析”，不显示 0 分。为空的薪资显示“未填写”，不显示 0–0K。

### 4.3 详情工作区

复用已有简历正文，整理为左侧简历、右侧操作与记录。右侧分为“备注记录”“岗位推荐”“自动任务记录”，避免把人工推荐和自动打招呼混在一起。

默认从列表打开宽抽屉，查看后保留查询；现有详情地址继续可直接访问，两处复用同一组组件。小屏采用单列布局。

## 5. 添加弹框：只保留两种方式

### 5.1 手动添加

1. 点击右上角“添加”，选择“手动添加”。
2. 基础区：姓名、手机号必填；邮箱、性别、出生年月、当前地区、期望地区、学历、工作年限、求职状态、期望职位、薪资选填。
3. 可按需展开工作、教育、项目、证书、荣誉和个人优势；不要求用户一次填完整份简历。
4. 可选关联岗位和首条备注。选择岗位只建立关联；明确点击“推荐到岗位”才记推荐动作。
5. 手机号变化后查重。确定重复时先展示可访问的已有候选人，可打开已有简历、仅加备注/关联岗位，或比较字段后更新。
6. 保存后进入详情，保留新增来源、入库人和时间。

### 5.2 AI 批量解析

推荐由本地 Agent 完成文件提取、OCR 与 AI，云端只保存用户确认的结构化简历和任务摘要。这样与现有架构一致；手动添加、插件基本采集不要求 Agent 在线。

1. 选择多个文件，或粘贴一份简历文本；初期支持 PDF、DOCX、TXT、PNG/JPEG。
2. 校验格式、数量和大小，估算调用量。建议初始限额为每批 20 个、单文件 20MB，可配置；不支持的 DOC、压缩包等给明确提示，不伪装成解析成功。
3. 普通 PDF/DOCX 提取正文；扫描 PDF/图片走本地 OCR。新增通用“简历解析”流程，复用 AI 结构化模型，不借用主动打招呼流程、评分或任务统计。
4. 显示每个文件状态：排队、解析中、待补手机号、可能重复、待确认、已入库、失败。
5. 解析结果是草稿。用户可修正姓名、手机号、经历和岗位；没有有效手机号不能勾选正式入库。
6. 批量确认后写入，不重复创建；批内相同手机号也提示冲突。只重试失败项，已入库项不再次调用 AI 或写入。
7. 任务和逐文件结果持久化到本地 SQLite；浏览器关页或 Agent 重启后可恢复状态，运行中项重新排队；主动取消后停止新增调用，保留已完成结果。
8. 原文件、截图、OCR 临时文件留本地；云端不保存这些文件，也不新增不可用的云端附件链接。跨电脑查看原附件和在线附件下载不在首期范围。

建议成本规则：手动新增、查重、备注和推荐不消耗 AI；批量解析仅实际发起 AI 时按现有规则计费，并在开始前提示。取消或重试不重复扣已经完成项的费用。

## 6. 字段差异与统一模型

当前数据库实际存储以 `candidate_store_pg.go`、0050 迁移和 `StructuredCandidate` 为准。旧 `candidate.go` 的附件、扩展等结构不代表这些列仍然存在。

| Hi Match 字段/能力 | GoodHR 当前字段/能力 | 处理方式 |
| --- | --- | --- |
| name、phone、email、birthYm | candidate_name、phone、email、birth_ym | 保留，统一姓名和手机号校验 |
| gender、age、avatarUrl | 性别、头像未在当前主体持久化；年龄可由出生年月推算 | 增性别；年龄优先推算，无生日时允许记录估计年龄和来源；首期默认文字头像 |
| city、expectedCity | work_region 混合当前/期望地区 | 新增 current_region、expected_region；保留旧 work_region，不盲目拆分历史值 |
| workYears | work_years 文本 | 保留原文，增加可查询的年限数值；未知值为 null |
| currentSalary、expectedSalary、expectedSalaryMin/Max | expected_salary_min/max，当前整型并按 K 展示 | 保留 K，数值类型调整为可保存小数 K 并同步模型；旧整数原值保留，元/月明确换算、不四舍五入丢金额；保留薪资说明原文 |
| educationLevel、expectedPosition、workStatus | 同等基础字段 | 复用，映射值并保留未识别的文本 |
| 工作/教育/项目/证书/荣誉 | 对应 JSONB 数组 | 复用；统一公司、职位、学校、专业及 YYYY-MM，至今不伪造结束日期 |
| AI 总结 | 详情/招呼分数与原因 | 增可选 ai_summary，和原有任务评分分开 |
| source、tags、owner、status | 单平台来源、创建人；没有完整库状态/标签 | 增 source_type、tags、library_status；不默认引入负责人转交流程 |
| 多个平台候选人身份 | 主体只有首次平台/候选人 ID | 增来源映射表，一个人可保留多个平台身份和来源 URL |
| 附件列表 | 0050 已删除实际附件 URL/提取文本列 | 首期本地文件元数据，不复活旧字段假装支持云端附件 |
| EntityNote | candidate_events 的 manual_note | 复用；保留正文换行，补操作人姓名，最新在前 |
| Recommendation、推进历史 | 自动任务 engagement，没有人工推荐模型 | 新增独立关系和推进历史，复用已有岗位 |

备注与简历编辑保持独立。新简历填写首条备注时，先取得候选人 ID，再调用备注接口；备注失败保留草稿和重试入口，不再次创建简历。已有简历必须明确点“加备注”，更新简历不会隐式提交备注。

## 7. 查重、安全更新与历史兼容

- 手机号标准化：去空格/分隔符，统一大陆号码的 +86 前缀；国际号码单独保存国家码。掩码号码、不完整号码和 OCR 低可信号码不能当作有效手机号，应手工确认。
- 确定重复：相同有效手机号，或相同平台和候选人 ID；展示匹配原因。
- 可能重复：姓名结合公司、学校、职位、年龄等线索；只提醒，不自动合并。用户确认后才能将新来源关联到已有简历。
- 并发新增由数据库约束、事务与幂等键共同保护，不能只依赖按钮禁用或保存前一次查询。
- 现有数据可能有跨平台同手机号记录。迁移前只读统计并备份；不批量删除、不自动合并历史记录，不直接加会导致上线失败的全量手机号唯一索引。
- 建手机号索引供查询；新增 `candidate_phone_identities` 团队内手机号身份登记表，对新入库的已确认身份加唯一约束。历史多条命中进入人工选择，不能随意选第一条；号码变更要留下审计。
- 增 `candidate_profile_sources`，非空平台候选人 ID 建团队内唯一约束。旧首次来源字段保留，逐步兼容自动任务同步。
- 更新采用字段差异预览、版本检查和人工字段保护：空电话、空数组、空字符串不会覆盖已有有效值。用户主动清空与采集缺失必须区分。
- 新的候选人新增/编辑接口不调用岗位运行入库接口；手动和插件新增、备注、推荐均不增加扫描、分析、招呼统计。
- 当前普通成员只看自己创建的简历，管理员看团队。首期保留权限：查重可提示“团队内可能已有，请管理员协助”，但不泄露无权限简历的姓名、手机号或备注；更新、关联和推荐须逐项校验权限。
- 岗位删除后推荐历史保留岗位名称快照；候选人手机号等字段变化不丢失备注和推荐记录。

## 8. 岗位关联与推荐记录

新增候选人与岗位的多对多人工关系，独立于自动任务的 `candidate_engagements`。

- 一位候选人可关联多个已有岗位，同一候选人与同一岗位只建立一条关系。
- “关联岗位”默认待推荐；“推荐到岗位”记录推荐人、推荐时间、岗位名称快照和推荐备注。
- 首期阶段建议为待推荐、已推荐、沟通中、面试中、Offer、已入职、暂不推进；不复制参考项目的客户、合同、佣金和可自定义全流程 CRM。
- 每次明确修改阶段追加历史：操作人、时间、前后阶段、内容；刷新或重复点击不能推进阶段。
- 简历详情展示全部推荐关系；岗位页增“候选人/推荐记录”入口。现有岗位开始、停止、平台配置和运行日志不受影响。
- 推荐备注属于该岗位推进记录；候选人通用备注仍走现有 `/notes`，避免在多个岗位中混淆。

建议数据表：`candidate_recommendations` 与 `candidate_recommendation_events`。候选人与岗位关系设团队内唯一约束；事件只追加，记录操作者和快照。

## 9. Chrome 与 Firefox 插件

### 9.1 规则冲突：实施前必须确认

仓库 `AGENTS.md` 的最高优先级规则明确：

> 严禁向招聘页面注入 JavaScript，或修改页面 DOM、样式、滚动位置、焦点和运行状态。

原文同时要求：“如果标准能力无法完成需求，必须停下来向邓云川确认”。用户要求的自动出现页面悬浮框，以及参考插件的 content script 读取和浮层插入，均超出当前规则。

推荐最小例外，仅适用于新建的、用户主动安装的“手动简历采集插件”：

1. 允许在明确支持的候选人详情区域只读提取已经显示的信息，以及插入插件自己的隔离浮层。
2. 插件不修改招聘网站业务元素，不注入页面 MAIN world，不读取平台内部 JS 状态、不劫持接口、不自动点击按钮、不修改焦点或滚动、不突破掩码手机号。
3. 插件不控制已有自动化浏览器任务，不另起 Worker 或浏览器控制链路；本地 Go→Worker→Camoufox 的零注入规则继续严格执行。
4. 获得确认后才在规范文件中记录这项精确例外，再开发平台插件适配器。

若不接受例外，可改为浏览器工具栏弹窗/侧栏，用户粘贴文本或选择截图/文件再解析，不往招聘页面放浮层。没有页面脚本读取权限时，不能同时承诺自动识别当前候选人并弹出页面浮层。

### 9.2 平台与交互

首批支持猎聘企业端、猎聘猎头端、智联，分别验收独立详情页、页面内弹框以及 iframe 场景。参考项目没有猎聘企业端实现；需用真实账号页面核实其域名、详情结构和可见字段，不能按猎头端直接推断。

浮层平时收起为“添加到 GoodHR”；只有明确识别到候选人详情才出现。展开后显示：

```text
添加到 GoodHR                         当前账号 / 收起
姓名：……       手机号：[识别结果或手动填写]
查重：未发现 / 已有简历 / 可能重复（匹配原因）
岗位：[可输入搜索，可多选]     备注：[多行输入]
操作：添加 / 比较并更新 / 加备注 / 推荐到岗位
记录：最近备注与岗位推荐，点击查看全部
```

- 提交前显示将保存的字段；页面切换候选人时重置身份并保留对应草稿，不把上一位的手机号带入下一位。
- 无号码提示：“手机号暂时没认出来，补一下，我再帮你入库。”禁止用掩码或随意号码代替。
- 未解锁/未显示的手机号由用户填写，插件不自动购买或解锁联系方式。
- 浮层有收起、关闭和开关；采集选择器不匹配时提供手动补充，不静默保存错误正文。
- 只在点击保存时传送简历；自动查重传必要的身份线索，不上传整个页面、会话、平台 Cookie 或招聘网站密码。

### 9.3 包结构与安装

建议目录 `goodhr5/browser-extension/`：共享 api、auth、候选人模型、UI；平台适配器分别维护；Chrome/Firefox 各自 manifest 和 background 入口。

- Chrome 使用 MV3 service worker；Firefox 使用非持久 `background.scripts` 和固定扩展 ID，共享逻辑适配 `chrome`/`browser` API，不能只改文件后缀。[MDN 后台配置](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/manifest.json/background)
- 权限只覆盖 GoodHR 云端、必要的本地桥接和三个平台的具体域名；不默认申请全站访问。
- Chrome 首期交付可加载的解压包和安装说明；Firefox 普通正式版本交付需签名 XPI，临时加载仅供开发验证。上架/签名所需账号和发布动作在安装包可验收后处理。[Mozilla 签名与分发](https://extensionworkshop.com/documentation/publish/signing-and-distribution-overview/)、[Chrome 分发](https://developer.chrome.com/docs/extensions/how-to/distribute/install-extensions)
- Firefox 新扩展需按当前 Mozilla 要求声明个人数据采集权限与用途；不能把简历采集声明为不采集数据。旧 Firefox/Camoufox 底座需要兼容同意界面，实际底座版本在安装验证时核实。[Mozilla 数据采集同意](https://extensionworkshop.com/documentation/develop/firefox-builtin-data-consent/)
- 平台适配代码随插件包发布，不下载远程代码执行；后台持有凭证，业务消息做参数与发送来源校验。[Chrome MV3 要求](https://developer.chrome.com/docs/webstore/program-policies/mv3-requirements)
- Camoufox 当前具备加载本地解压扩展目录的链路，可作为后续集成点；新 Firefox 包仍需实际兼容验证，不能据此承诺普通 Firefox 与 Camoufox 一次通过。
- 不把插件包默默安装进正在运行的招聘浏览器；普通 Firefox、Chrome 和 Camoufox 分开验收。

## 10. 本地自动登录与手动登录

### 10.1 当前不能直接自动登录

网页已有登录后会通过 `/api/v1/session/bind` 把会话交给本地程序完成云端绑定；本地持有的相关会话目前用于诊断上传。现有 `/health` 不返回账号或 Token，也没有插件登录/会话交换接口。插件不能直接读取网页 localStorage 或从健康接口取登录态。

### 10.2 推荐方案：首次配对，之后自动恢复

1. 插件后台尝试发现本机 Agent 端口（复用实际端口规则）；发现只判断服务，不暴露 Token。
2. 新增本地统一会话管理器，复用 bind 后的已验证身份，发放插件授权前重新验证云端会话。用户首次点击“连接本地程序”，在已登录控制台确认将使用的 GoodHR 账号和权限；后续同一插件安装可自动恢复。
3. 新建一次性配对码/挑战和云端会话交换。配对码短时有效、单次使用，并绑定当前账号、插件安装身份和随机挑战；本地与云端都校验，不设无认证的“拿 Token”接口。
4. 云端签发受限插件会话，仅允许候选人查询/入库、备注、可访问岗位与推荐记录；不给系统管理、删除团队库或控制本地招聘任务权限。
5. 插件后台保存会话，content script 只发送明确业务消息，不收到 Token。续期、过期、撤销、退出和账号切换均有明确状态；不得借用另一账号的待保存草稿。
6. Agent 退出后，已有有效插件会话可继续用云端业务接口；过期且无法自动恢复时转手动登录。本地退出账号/云会话撤销后不再自动恢复原账号，明确撤销插件授权时立即使插件会话失效。

本地桥接只监听 loopback，需单独认证、限流和校验配对来源，不因支持插件就把现有 CORS 放开为 `*`。Chrome 扩展来源与 Firefox 扩展来源形式不同，不能仅凭 Origin 当作身份凭据；获 host_permissions 的扩展后台可以跨域请求，CORS 不是认证。[Chrome 网络请求](https://developer.chrome.com/docs/extensions/develop/concepts/network-requests)、[Firefox 主机权限](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/manifest.json/host_permissions)

### 10.3 手动登录

保留“手动登录 GoodHR”入口，复用当前邮箱验证码/密码等实际登录方式，建立同样的受限插件会话，不沿用 Hi Match 的账号密码接口。无需本地程序也可以查看、添加、查重、备注和人工推荐。

插件自身登录和招聘平台登录相互独立。插件不替用户登录猎聘/智联、不存招聘平台 Cookie，不读浏览器账号密码。需要 AI/OCR 文件解析时仍使用已授权的本地程序；未连接时说明下一步。
