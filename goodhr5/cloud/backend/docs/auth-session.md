# 登录有效期与持久化

本文说明登录会话的保存方式和升级注意事项。

- 新登录固定有效 30 天，访问页面不延长到期时间；退出、清除浏览器数据后需重新登录。
- 配置 PostgreSQL 时，会话存入 `auth_sessions`，仅保存凭证 SHA-256 摘要。后端重启不会丢失数据库中的有效会话。
- 启动自动执行 `0081_persistent_auth_sessions.sql`。请先发布后端，再发布前端。
- 原 Redis 中仍有效的会话在下次访问时迁入数据库，保留原到期时间，不额外续期。已经丢失或到期的旧会话无法恢复，需要重新登录。
- Redis 继续承担验证码存储；只有 Redis、没有 PostgreSQL 的环境仍依赖 Redis 自身持久化设置。
- 两者都未配置时属于纯内存开发模式，启动会警告，重启会丢失登录。
- 缺少或已失效的凭证返回 401 和明确错误码；认证存储临时故障返回 503，不清除前端凭证。
- 前端只清理该请求所使用且仍为当前值的失效凭证，防止旧请求退出新会话。

数据库集成测试使用独立的 `GOODHR_TEST_DATABASE_URL`；未配置时跳过，不操作开发 Docker。
