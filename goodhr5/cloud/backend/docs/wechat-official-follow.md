# 公众号关注绑定与会员奖励

未认证个人订阅号通过微信签名回调取得 OpenID。普通关注二维码不能可靠携带网站用户身份，因此使用「登录后台生成绑定码 → 扫码关注 → 向公众号发送绑定码」完成绑定。

微信官方带参二维码接口的账号权限见 [官方二维码文档](https://developers.weixin.qq.com/doc/service/api/qrcode/qrcodes/api_createqrcode.html)。本功能不拼接无效二维码参数，也不调用需要认证服务号权限的接口。

## 管理员配置

1. 打开「系统配置 → 其他配置 → 公众号」。填写公众号名称、AppID、原始 ID、Token、EncodingAESKey，保存。
2. 在微信公众平台的服务器配置填写：
   - URL：`https://goodhr.58it.cn/api/wechat-official/callback`
   - Token：复制系统配置中的 Token，两边完全相同。
   - EncodingAESKey：与系统配置保存的 43 位密钥相同。
   - 消息加密：推荐「安全模式」；系统配置的消息模式也选「安全模式」。
   - 数据格式：XML。
3. 微信验证 URL 成功并启用服务器配置后，再在系统配置打开「启用公众号绑定」并保存。

赠送天数与原注册赠送字段 `trial_days` 同组，位于「系统配置 → 本地组件 → 本地程序与组件」的 `system.onboarding_config.wechat_follow_reward_days`，默认 2 天，允许 1 到 365 的整数。页面提示、公众号回复、实际入账和奖励账本使用同一配置；只影响之后的首次领取，不重新发放或缩短已入账的会员。

此流程不需要 AppSecret。二维码默认使用微信官方图片地址，由 `gh_` 开头的原始 ID 生成；也可填入自己的 HTTPS 二维码图片地址。图片地址直接展示，不再次生成一个指向图片的网址二维码。

启用微信服务器配置前，请核对公众平台已有自动回复与自定义菜单的安排；平台服务器回调和平台原有回复功能的切换说明见 [官方接入文档](https://developers.weixin.qq.com/doc/subscription/guide/dev/push/)。本服务仅被动回复关注事件和绑定消息，软件最新通知仍可通过公众号文章、平台群发发布。

## 用户使用

- 未绑定用户进入控制台时，在更新、公告和必填提示处理完后显示关注弹框；可点「暂不关注」继续使用。
- 控制台保留「关注领会员」入口，可以随时重新打开；已领取过的用户显示「关注公众号」。
- 查看 4 位数字绑定码，扫码关注，再向公众号发送该码。绑定码有效期 10 分钟，重新生成后旧待绑定码失效。弹框底部同一行保留「暂不关注」和「重新生成」，不再显示复制按钮。
- 标题使用红色加粗的「关注领取 X 天会员」；正文操作说明加大、加粗并使用红色，便于忙碌时快速识别。
- 服务器收到有效关注事件和绑定码后，原子保存 OpenID、会员时间与奖励账本。后台用户管理显示「OpenID 有 / 无」，不展示原始 OpenID。
- 原来就已关注的用户，如果系统尚未观察到关注事件，需要取消后重新关注，再发送绑定码。单凭文本消息不能证明已关注。

## 奖励及边界

每个网站账号、每个公众号微信用户只赠送一次。有效 Plus / Max 会员保持原类型和到期时间，再增加配置天数；其他用户从当前时间获得配置天数的 Max。当前默认为 2 天。保留订阅 JSON 其他字段，不影响邀请奖励、支付记录或 AI 余额。

数字码使用密码学随机数，先由 Redis 原子占位、再由数据库事务防止碰撞，碰到占用码后重新随机。开发环境使用内存缓存。未过期的已完成或已作废码保留占位至原失效时间；过期后才允许复用。数据库中的创建时间校验阻止已发出的旧回调串入新绑定。每个账号十分钟最多生成五次，每个微信连续错码五次后暂停新绑定十分钟。四位码仅用于已有网站账号的关注绑定，不用于网站登录。

取消关注后清除原始 OpenID 绑定。永久奖励账本和单向 OpenID 指纹用于防止重复领取；重新关注可以重新绑定，但不会重复赠送。乱序到达的旧取消关注事件不会覆盖新关注状态。同秒冲突保守地按取消关注处理，用户可稍后重新关注。

公众号私有配置独立存于 `system.wechat_official_account`，不放入公开的 `system.app_config`。AES 密钥不会返回前端；超管只看到是否已配置，空白保存保留原密钥，填写新密钥才覆盖。Token 仅在超管配置中显示以便复制。

## 验证与部署

本地测试使用独立签名与 AES 协议夹具，验证消息签名、加密目标、填充、过期码、并发领取、取消重关和会员保持；PostgreSQL 测试使用隔离数据库。模拟测试不能替代微信平台真实扫码验收。

生产发布同时更新后端和前端。初版启动自动迁移执行 `0084_wechat_follow_gift.sql`，天数配置版执行 `0085_wechat_follow_reward_config.sql`，后者只给原配置增加关注赠送字段，不改注册试用或本地程序下载信息。上线前保留数据库备份与旧容器；回退时恢复旧容器并关闭新功能，已入账的奖励记录应保留，不能直接删除新表或恢复旧数据库覆盖上线后的业务数据。

本功能不变更本地 Agent、浏览器 Worker、下载更新配置或招聘执行逻辑。
