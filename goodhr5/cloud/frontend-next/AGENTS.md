# Prototype Instructions

Run the local server yourself and open the preview in the in-app browser. Do not give the user server-start instructions when you can run it.

Before making substantial visual changes, use the Product Design plugin's `get-context` skill when the visual source is unclear or no longer matches the current goal. When the user gives durable prototype-specific design feedback, preferences, or decisions, record them in `AGENTS.md`.

When implementing from a selected generated mock, treat that image as the source of truth for layout, component anatomy, density, spacing, color, typography, visible content, and hierarchy.

## GoodHR 新版前端设计约定

- 官网和后台统一使用 Next.js + Ant Design，后台所有可由组件实现的内容优先使用 Ant Design 组件；官网允许独立 HTML/CSS 排版，并保持服务端预渲染和 SEO。
- 视觉以明亮、简洁、留白充足为主，使用绿色品牌强调，不使用深色主题和蓝紫渐变。
- 首页参考 SeeLink 浅色排版结构，但不使用右侧产品卡片，首屏以单栏品牌信息和真实统计为主。
- 卡片圆角不超过 8px，避免大量卡片嵌套和无意义装饰。
- 官网、登录页和后台的常规操作按钮统一胶囊圆角；弹框底部的取消、确认等操作统一靠右。下拉选择框默认支持输入筛选。
- 后台搜索区输入保持紧凑高度，操作按钮按内容宽度；余额卡按内容自适应。用户管理表格明确列宽，金额和日期不得逐字换行，流程卡点摘要最多 40 字符含省略号，全文可查看。
- 官网公开页面使用 Next.js 服务端预渲染；公开统计只允许在服务端读取，浏览器不得直接请求云端统计接口。
- 官网导航在桌面和手机端都必须直接显示“今日处理简历、今日注册”统计，不得只放进移动端抽屉。
- 官网所有下载主按钮先进入 `/download`，由下载页统一提供各系统安装包，不在首页直接链接安装文件。
- 官网 SEO 与 GEO 使用可见正文、自然问答、JSON-LD、站点地图和 `llms.txt`；覆盖主流招聘平台与自动打招呼、AI筛选、自动回复、简历下载等组合场景，但不使用隐藏文字。
- 任意官网地址中的 `invite` 参数由全局组件写入 `goodhr5_invite_id`，登录时统一提交，页面之间不得重复实现邀请参数逻辑。
- 新后台统一使用 `AdminApp`、`admin-api` 和 `AdminUI`；云端业务数据走云端 API，本地任务和浏览器操作只走 Local Agent。
- 本地程序更新由 Agent 下载和安装，前端只提交既有更新接口并串行读取进度。安装时断线必须继续重连，重新连接、账号绑定和版本同步完成后才结束更新弹框；慢请求不得叠加，离开后台后不得恢复旧弹框。更新回归使用模拟安装，不操作真实安装包。
- 后台采用左侧菜单、顶部状态栏、主内容区三块独立悬浮面板；菜单按工作台、招聘管理、团队与账户、本地与帮助、系统管理分组。
- 桌面左侧菜单保持紧凑，宽度为 200px；顶部状态栏和内容区共用侧栏宽度变量同步对齐。
- 后台顶部状态栏不显示边框；未选中的侧栏文字和图标使用柔和中性色，避免与页面内容争抢视觉焦点。
- 后台顶部状态栏长期保留醒目的“视频教程”入口，桌面显示按钮，手机显示播放图标。
- 后台输入框和按钮使用紧凑工作台尺寸；输入框与按钮同行时必须限制输入区域宽度，并保证按钮不被压缩或换字。
- 简历库采用紧凑排版：正文和姓名13px、辅助信息12px、常规控件32px；最新备注正文及作者时间固定12px、普通字重，避免继承按钮的加粗，悬停及按下不显示底色或阴影，保留点击与键盘焦点；求职意向并入候选人第一列，保留期望职位、地区、薪资和求职状态，不再单独占列。
- 简历库候选人姓名下的基础信息、求职意向与标签统一为12px普通字重和辅助文字色，每个属性独立并随列宽自动换行，长属性可内部折行；性别显示中文，数字工作年限补单位；创建时间列只展示创建日期及时间，来源和创建人仍在详情与筛选中保留。
- 管理员日志使用紧凑列表，每条日志收起时只占一行；默认显示时间、类型、账号、岗位和中文摘要，完整错误和入参出参点击后展开，不使用逐条卡片或把原始 JSON 放在摘要中。
- 岗位卡片的开始和停止共用一个状态按钮；开始使用当前会员主题的主色实心样式，停止使用红色实心样式，确保关键运行操作醒目。
- 岗位卡片的日志、编辑和删除只展示图标，悬停显示中文提示；三个操作保持横排，每个点击区 28px、间距 4px，避免挤占岗位信息。
- 会员专属选择卡使用纯黑金配色，不使用渐变；普通功能卡继续使用当前主题色。
- 新增和编辑表单统一使用 `AdminDialog`，模式选择统一使用 `ChoiceCards`，系统 JSON 配置统一使用 `JsonEditor` 和 `JsonTree`。
- 岗位运行置顶小窗不展示岗位名；绿色表示运行中、红色表示已停止。候选人姓名是主信息，必须放在分析类型上方并使用更醒目的字号；AI 请求期间必须显示转圈动画。主区域长期保留 AI 分数、阈值、原因或关键词命中结果，普通浏览器步骤只放在底部小字，不能立即覆盖最终分析结果；窗口整体高度保持紧凑，避免状态下方出现大面积空白。
- 岗位运行置顶小窗默认尺寸为 340×250px；用户要求在原 220px 高度上增加 30px。
- 后台主题由有效会员类型自动决定：免费版使用松绿色、Plus 使用深墨黑、Max 使用低饱和黑金色；主按钮、会员状态、选中项、重点链接和装饰背景必须使用主题变量，不得写死绿色；运行中、连接成功等业务状态保留绿色，停止和错误保留红色，警告保留橙色，Logo 保持原色；不做整页深色主题，不使用渐变，也不允许用户手动切换或使用浏览器缓存覆盖。
- 公开路由使用无扩展名地址，同时保留旧 `.html` 地址的永久重定向，避免损失已有搜索入口。
