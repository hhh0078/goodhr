# Prototype Instructions

Run the local server yourself and open the preview in the in-app browser. Do not give the user server-start instructions when you can run it.

Before making substantial visual changes, use the Product Design plugin's `get-context` skill when the visual source is unclear or no longer matches the current goal. When the user gives durable prototype-specific design feedback, preferences, or decisions, record them in `AGENTS.md`.

When implementing from a selected generated mock, treat that image as the source of truth for layout, component anatomy, density, spacing, color, typography, visible content, and hierarchy.

## 新手引导约定

- 首次先邀请参加教程；无需教程需输入 `让开，我不需要教程` 二次确认。文案短、有人味，可轻微幽默。
- 使用可交互遮罩逐项教学，按当前路由和真实操作自动前进；不提供下一步，保留上一步、稍后继续和遇到问题。
- “上一步”必须真实回退，不能代替“遇到问题”打开帮助。岗位保存后回退应复核原岗位并保存同一ID；进度条、帮助和暂停入口提供“从头开始”，仅重置本机教学及对应未保存草稿，保留业务岗位和云端完成事实。运行中或保存、启动在途时不得重走造成重复任务；同账号复核草稿按岗位ID隔离。
- 教程顺序固定为准备本地程序、创建岗位、登录招聘平台、筛选并开始、看到筛选结果。岗位表单先确认平台，再逐项填写名称、筛选方式、详情识别和当前模式需要的要求或关键词；每一项都有可操作遮罩。名称必须提示到所选招聘平台“岗位管理”复制完整名称并保持一致。平台直接在岗位表单选择，不在保存前单独开浏览器或显示重复平台选择面板。
- 岗位真实保存成功后，先高亮该岗位的“开始”，再高亮现有开始弹框里的“打开平台，并筛选条件”，不借用顶部浏览器按钮或另外造入口。打开对应平台后，提醒在招聘浏览器里登录并设置年龄、学历、地区等条件；连续登录确认后，高亮“我已筛选好，立即开始”，由用户确认平台筛选条件。确认运行不得重新导航平台入口而丢失已设条件。刷新后弹框不自动重开，回到该岗位“开始”恢复准备。
- 筛选方式在遮罩和选项卡同时说明费用及场景：关键词基础筛选免费，适合单一简单条件；AI适合复杂、多项要求，需要会员，内置AI按用量扣余额、自定义接口按服务商规则计费。关键词配AI详情仍有AI费用；提示不改变默认值、扣费规则和启动门槛。
- 顶部显示五阶段进度及预计剩余时间；按账号在本机保存进度和核心岗位草稿，云端真实完成事实保持优先。恢复草稿保留用户实际选择的平台；平台关闭时保留其他字段并引导重选，不强制恢复为 BOSS。
- 教程及暂停待继续时不自动弹出公告、普通更新或推广；必要更新和强制安装沿用业务检查并协调遮罩。
- 岗位教学仅展示核心字段及当前模式需要的要求或关键词；每一步有说明，真实终态筛选后给予鼓励和礼炮，兼容减少动态效果。

## 后台前端开发标准（优先执行）

所有后台菜单、详情、表单与弹框以简历库顶部的紧凑控件为尺寸基准，先复用 `app/theme.ts` 的 `createGoodHRAdminTheme`、`AdminUI` 及 `app/admin.css`，不要为单页重复设置整套尺寸。

- 常规按钮、输入框、选择框、数字框、日期框、岗位状态选择统一32px高，正文13px、辅助文字12px；同一工具栏必须同高并垂直居中。工具栏禁止随意使用small/large或写死不同height/fontSize。紧凑表格行操作26px、图标操作28px、收藏夹小栏25px属于明确例外；多行输入保持正常自适应。
- 控件间距8px，工具栏与下方表格/卡片至少12px。使用 `goodhr-compact-toolbar`；左侧查询和筛选，右侧新增、新建、邀请、生成等主操作放在 `goodhr-toolbar-actions`。不得把新增紧挨左侧筛选，桌面不换行；手机宽度不超过599px时筛选自然换行，新增按钮保持可见并靠右，不能把主操作藏在横向滚动末尾。
- 页面内容遵循现有统一容器边距，卡片不得无故贴边；表格单元格横向12px、纵向10px。独立分页使用 `goodhr-table-pagination`、四周12px内边距、组间8px；Table内置分页上下至少12px、左右12px，页码和每页数量选择框统一32px，窄屏能自然换行。
- 后台各菜单和普通资料弹框不得新增独立刷新按钮，包括文字或图标刷新、刷新状态/进度/预览；用户需要时刷新页面。保留首次读取、保存后自动更新、任务轮询，以及实际失败时的重试、安装后检查、重新连接等明确业务动作。
- Ant Design Flex会重置margin和padding，共享工具栏、右侧操作组、分页容器必须保证样式优先级高于.ant-flex，并用真实页面尺寸验证生效；不能只看源文件已写间距。
- 不用全局!important强推控件高度，不让样式穿透官网、登录或公开邀请页。局部布局可复用共享类，避免局部margin:0/padding:0取消工具栏与分页留白；保留字段筛选、保存、删除、权限与加载状态等原功能。
- 合并前必须自己看桌面和手机截图；至少检查岗位管理、简历库、猎头推荐、企业招聘以及本次受影响的其他菜单，检查同排控件高度、新增靠右、表格/分页边距、空数据、长文本、翻页和无独立刷新。验证用合成账号和模拟API，不能为截图改真实业务数据。类型检查、相关单测和UI回归通过后再发布。

## GoodHR 新版前端设计约定

- 候选人、面试和猎头推荐详情统一使用接近全屏的大弹层：桌面左侧约七成展示候选人资料与标签页，右侧约三成展示流程、操作和备注；手机改为可滚动的单栏。面试按轮次和时间倒序展示时间线卡片，上半为安排信息，下半为逐位评价与未评价人员；推荐历史沿用同样的时间线层次。保留现有流程、历史和服务端权限，颜色继续使用用户主题。详情层必须低于其上打开的编辑、面评和确认弹框。

- 企业招聘、猎头推荐、岗位管理三个页面不展示页面大标题或副标题说明；查询、筛选、状态切换、新增及页面内设置入口放在同一条紧凑工具栏。桌面不换行，宽度不足时缩短输入或横向滚动；手机筛选自然换行、新增靠右且直接可见，所有操作保持可用。侧栏不展示招聘设置，企业招聘页内保留设置弹框入口，旧设置路由继续复用相同内容。
- 简历原始标签 `tags` 保留自由输入和原文展示；个人与团队收藏夹使用独立 `folder_ids` / `folder_details`，不能从原始标签自动创建或加入。简历库表格不单独展示收藏夹列，保留收藏夹筛选、管理弹框、编辑选择和按账号隔离的最近使用缓存；删除收藏夹不删除简历或原始标签。
- 个人配置页不展示顶部页面标题和说明；通知偏好、保存配置保持可用。分类选项栏和当前配置内容放在同一个白色面板内，AI 配置不使用整块主题色背景，其他页面不受影响。

- 官网和后台统一使用 Next.js + Ant Design，后台所有可由组件实现的内容优先使用 Ant Design 组件；官网允许独立 HTML/CSS 排版，并保持服务端预渲染和 SEO。
- 视觉以明亮、简洁、留白充足为主，使用绿色品牌强调，不使用深色主题和蓝紫渐变。
- 首页参考 SeeLink 浅色排版结构，但不使用右侧产品卡片，首屏以单栏品牌信息和真实统计为主。
- 卡片圆角不超过 8px，避免大量卡片嵌套和无意义装饰。
- 官网、登录页和后台的常规操作按钮统一胶囊圆角；弹框底部的取消、确认等操作统一靠右。下拉选择框默认支持输入筛选。
- 后台搜索区输入保持紧凑高度，操作按钮按内容宽度；订阅页的余额卡和会员卡按可用宽度自适应。用户管理表格明确列宽，金额和日期不得逐字换行，流程卡点摘要最多 40 字符含省略号，全文可查看。
- 用户管理用紧凑“简历数”列显示每个账号创建的真实简历数量，只显示数字；团队共享、岗位推荐和内置瓜瓜示例不重复计数，手机卡片同样显示数量。
- 官网公开页面使用 Next.js 服务端预渲染；公开统计只允许在服务端读取，浏览器不得直接请求云端统计接口。
- 官网导航在桌面和手机端都必须直接显示“今日处理简历、今日注册”统计，不得只放进移动端抽屉。
- 官网所有下载主按钮先进入 `/download`，由下载页统一提供各系统安装包，不在首页直接链接安装文件。
- 官网 SEO 与 GEO 使用可见正文、自然问答、JSON-LD、站点地图和 `llms.txt`；覆盖主流招聘平台与自动打招呼、AI筛选、自动回复、简历下载等组合场景，但不使用隐藏文字。
- 任意官网地址中的 `invite` 参数由全局组件写入 `goodhr5_invite_id`，登录时统一提交，页面之间不得重复实现邀请参数逻辑。
- 新后台统一使用 `AdminApp`、`admin-api` 和 `AdminUI`；云端业务数据走云端 API，本地任务和浏览器操作只走 Local Agent。
- 本地程序更新由 Agent 下载和安装，前端只提交既有更新接口并串行读取进度。安装时断线必须继续重连，重新连接、账号绑定和版本同步完成后才结束更新弹框；慢请求不得叠加，离开后台后不得恢复旧弹框。更新回归使用模拟安装，不操作真实安装包。
- 后台采用左侧菜单、顶部状态栏、主内容区三块独立悬浮面板；菜单按工作台、招聘管理、团队与账户、本地与帮助、系统管理分组。
- 桌面左侧菜单保持紧凑，宽度为 200px；顶部状态栏和内容区共用侧栏宽度变量同步对齐。
- 后台顶部状态栏不显示边框；未选中的侧栏文字和图标使用柔和中性色，避免与页面内容争抢视觉焦点。
- 后台顶部状态栏长期保留醒目的“视频教程”入口，桌面显示按钮，手机显示播放图标。
- 后台输入框和按钮使用紧凑工作台尺寸；输入框与按钮同行时必须限制输入区域宽度，并保证按钮不被压缩或换字。
- 简历库采用紧凑排版：正文和姓名13px、辅助信息12px、常规控件32px；最新备注正文及作者时间固定12px、普通字重，避免继承按钮的加粗，悬停及按下不显示底色或阴影，保留点击与键盘焦点；求职意向并入候选人第一列，保留期望职位、地区、薪资和求职状态，不再单独占列。
- 简历库候选人姓名下的基础信息、求职意向与标签统一为12px普通字重和辅助文字色，每个属性独立并随列宽自动换行，长属性可内部折行；性别显示中文，数字工作年限补单位；创建时间列展示创建日期及时分，并保留来源、平台和创建人。
- 简历库手机号自然跟在姓名后面，头像与候选人文字整体垂直居中；工作经历只强调公司名称，职位和日期保持普通字重。添加简历在同一个弹框中以 AI 批量上传、手动添加、浏览器插件一键导入三个标签直接切换，切换保留未提交草稿，插件标签提供准确的可用版本说明及官网下载入口。
- 官网下载页将本地程序下载与浏览器插件下载分成独立区域，下载入口优先展示；本地程序更新记录默认最近三条，通过“展示更多”和“收起”控制完整历史，不删除旧版本配置。
- 官网下载页不展示大幅下载首屏和分类锚点按钮，直接进入本地程序下载；下载卡片使用紧凑间距，图标与系统或浏览器名称同行。
- 官网下载页的 Windows 和 macOS 本地程序入口先展示对应系统的安装说明，弹框内再提供真实下载按钮；Windows 说明关闭可能拦截安装的安全软件并直接在压缩包内运行安装程序，无需解压，macOS 说明未签名程序的“仍要打开”路径，两端都提供安装失败时联系作者的提示，并保留无 JavaScript 时的直接下载能力。
- 简历库登录后显示管理员内置的“瓜瓜”虚构示例，保持只读；列表只提供查看，详情不展示编辑、加备注、推荐保存或AI写入入口。真实候选人数量和权限沿用原规则，示例不参与查重、岗位任务或运行统计。
- 候选人详情的历史备注区域必须限制最大高度并在区域内滚动；输入框与“加备注”按钮保持同一行，不能因为备注数量增加而持续撑高整个详情区域。
- 简历详情减少资料段落和经历间的留白；右侧按备注、推荐、自动任务竖向排列。推荐区可隐藏或展示，按账号记住当前浏览器的选择，隐藏保留草稿；备注与自动任务常驻。不同岗位用可横向滚动的小卡片切换，选中卡片在上方表单修改，并直接展示该岗位的全部跟进记录，不显示“推进记录”计数或重复人员时间，不再使用“继续跟进”按钮。推荐状态使用单选框；保存才记录新跟进，不把历史备注重复提交。推荐区不显示两段操作说明；“加备注”和推荐保存使用按内容宽度的小按钮，统一靠右。
- 管理员日志使用紧凑列表，每条日志收起时只占一行；默认显示时间、类型、账号、岗位和中文摘要，完整错误和入参出参点击后展开，不使用逐条卡片或把原始 JSON 放在摘要中。
- 岗位卡片的开始和停止共用一个状态按钮；开始使用当前用户主题的主色实心样式，停止使用红色实心样式，确保关键运行操作醒目。
- 岗位卡片的日志、编辑和删除只展示图标，悬停显示中文提示；三个操作保持横排，每个点击区 28px、间距 4px，避免挤占岗位信息。
- 会员专属选择卡使用纯黑金配色，不使用渐变；普通功能卡继续使用当前主题色。
- 新增和编辑表单统一使用 `AdminDialog`，模式选择统一使用 `ChoiceCards`，系统 JSON 配置统一使用 `JsonEditor` 和 `JsonTree`。
- AI 充值弹框先展示金额输入，活动选项放在输入框下方，使用紧凑小选项并随屏幕宽度换行；有活动时默认选中第一个套餐及对应金额，无活动时默认 10 元，用户手动修改后保留已填金额。
- 会员激活码使用弹框填写；入口放在订阅会员页头的“退款”按钮左边，页面内不常驻激活码输入区域，失败时保留已填内容方便重试。
- 订阅页顶部的“当前会员”和“AI 余额”使用自适应等宽网格；空间足够时同一行等宽等高，空间不足时自动上下排列并占满可用宽度，卡内文字和操作不得溢出。
- 个人配置只保留一个 AI 配置标签，以自定义接口表单为基础，右上角提供“使用内置 AI”；API 地址必须为 HTTP(S)、不含用户信息，且解析后的主机与当前网站域名完全一致时，模型才使用公共配置 `builtin_ai.models` 的单选列表并展示提示和价格，无效模型回到首项；外部 API 地址保留模型自由输入，不得通过路径或查询字符串中的域名误判。
- 岗位运行置顶小窗不展示岗位名；绿色表示运行中、红色表示已停止。候选人姓名是主信息，必须放在分析类型上方并使用更醒目的字号；AI 请求期间必须显示转圈动画。主区域长期保留 AI 分数、阈值、原因或关键词命中结果，普通浏览器步骤只放在底部小字，不能立即覆盖最终分析结果；窗口整体高度保持紧凑，避免状态下方出现大面积空白。
- 岗位运行置顶小窗默认尺寸为 340×250px；用户要求在原 220px 高度上增加 30px。
- 后台主题由用户自由选择松绿色、深墨黑或低饱和黑金色，所有账号默认松绿色，不随会员类型自动变化；选择即时生效并按账号在当前浏览器保存，退出及公开页面使用默认绿色。主按钮、会员状态、选中项、重点链接和装饰背景必须使用主题变量，不得写死绿色；运行中、连接成功等业务状态保留绿色，停止和错误保留红色，警告保留橙色，Logo 保持原色；不做整页深色主题，不使用渐变。
- 公开路由使用无扩展名地址，同时保留旧 `.html` 地址的永久重定向，避免损失已有搜索入口。
- 公众号关注弹框保持紧凑：顶部仅一行红色粗体“关注领取 {动态天数} 天会员”，已领过时改为“关注公众号”，不叠加描述、公众号名称或奖励卡片；正文“先扫码关注，再把下面的绑定码发给公众号。”使用 18–20px 红色粗体，4 位数字绑定码醒目可读，有效期显示分秒。底部只有同一行靠右的“暂不关注”“重新生成”两个胶囊按钮，不提供复制或二维码失败按钮。奖励天数读取本人状态，缺省为 2；后台仅编辑 `system.onboarding_config.wechat_follow_reward_days`（1–365 整数），保留注册试用和本地组件等其他 JSON 字段。

## AI 助手与猎头客户约定

- 顶部 AI 助手入口仅显示图标，保留中文无障碍名称和悬停提示；关闭弹框不停止任务。企业招聘放在 HR 分类，客户管理、客户岗位管理和猎头推荐放在猎头分类，现有平台岗位与简历库继续共用。
- 助手只处理完整且校验通过的 JSON 事件；刷新主动接回既有任务，以事件编号补发去重，网络结果不明时使用原请求编号核对，禁止盲目新建付费任务。
- 会话按团队与账号隔离，IndexedDB 最多保存十个且不设应用时间期限；后台任务保留两小时，只由用户新消息续期。正文出现时收起思考摘要，工具调用的名称、入参、出参、耗时及尝试次数可折叠查看。
- 简历库设置内提供向量化总数、当前版本已完成数和独立启动按钮。启动只等待后台任务受理，提示稍后刷新；状态和内置 AI 资格由服务端返回，不在浏览器发起模型请求或处理 AI Key。
