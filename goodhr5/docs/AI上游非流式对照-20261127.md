本轮将内置 Chat Completions 发往主、备用平台的请求统一设为 `stream:false`，移除仅流式使用的 `stream_options`。模型、密钥、接口、消息、图片、思考配置、评分和结构化简历合同保持原值。向量接口不受影响。

旧本地程序仍可提交 `stream:true`。后端等待完整 JSON 结果并校验后，才将它一次性包装成兼容 SSE，保留消息、工具调用索引、usage 和唯一 DONE；计费回执仍在 DONE 前写入。原先请求 JSON 的客户端继续接收 JSON。这个兼容外壳不表示模型正在流式生成：判断实际模式应看后端每次尝试的 `upstream_stream:false`。

上游失败仍沿用现有四次预算、备用地址/模型/密钥切换、取消及余额保护。日志继续保存 HTTP 状态、完整脱敏错误、主备每次失败和时间线；JSON 上游正常结束记录 EOF，不伪造上游 DONE。若服务商无视 stream:false 返回 SSE，保留已有解析和 DONE 收尾能力。

合成回归覆盖：主备均非流式、图片/思考字段不丢、SSE/JSON 旧客户端、工具调用、结构化结果、实际账单、HTTP503和格式错误、恶意私有协议字段。后端完整包及定向 race 测试通过后，与恢复主站域名的改动一起推主分支。

上线后：核对真实容器源码与同一发布的隔离验收；通过 GoodHR 启动指定 BOSS 岗位，读取本机 task_runs 与 candidate_records，等本轮50个成功招呼及自然结束；逐次按请求ID关联后端非流式标志、耗时、错误和备用结果。域名与传输模式同时改变，本轮是组合验证，不能仅据结果改善就断言某一个变更单独解决了全部问题。

不制作桌面新安装包：此次只改云端代理，Windows、macOS的既有客户端通过原协议继续工作。新增日志字段完整保存在服务器，旧版岗位界面不展示新增字段。
