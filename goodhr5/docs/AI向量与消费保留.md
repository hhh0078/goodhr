# AI向量与消费保留

## 向量调用

- 主接口：`POST /api/ai-compatible/v1/embeddings`，使用个人内置AI Key的Bearer请求头。
- 输入：`{"model":"qwen3.7-text-embedding-flash","input":["一段工作经历"],"encoding_format":"float"}`。`model`和`encoding_format`可省略；每批1～20段，每段最多16000字、整批最多128000字。
- 固定使用默认1024维向量；返回索引必须覆盖全部输入、无重复、无空向量。模型、维度、数值和usage核对失败不写入钱包消费。
- 价格按本次确认的官方中国北京同步接口价格执行：输入0.125元/百万Token，输出不收费。钱包以0.0001元为单位向上取整，向量维度不作为输出Token收费。后台异步任务仍调用同步向量接口，不能套用官方Batch接口的0.063元输入价。
- 与聊天复用系统内置上游地址和Key，地址后缀切换为`/embeddings`，保留兼容路径；不会把向量模型加入聊天模型列表。
- 后台调用使用`AIWalletService.EmbedForUser(ctx, email, texts)`，邮箱必须来自已认证账号。用户需要启用当前站点的内置AI配置，且内置Key确实属于本人。
- 站点识别解析URL后精确比较主机名，路径、查询参数、子域及相似域名都不能冒充站内地址。
- 网络中断或扣款回执不明时明确返回未确认状态，不自动重试付费请求；上层应保留本次任务回执，避免刷新重放。

## 简历库后台向量化

`GET /api/resume-library/vectors`只统计当前账号有权查看的真实简历，返回`total`、`indexed`、`pending`及任务状态，示例简历不参与。完成数只承认当前简历行版本、固定模型方案和全部索引写入成功的记录。

`POST /api/resume-library/vectors`立即返回202和`task_id`，后台继续逐份处理，关闭弹框、刷新或断网不会取消任务。每个账号只有一个活动任务，正式环境复用Redis协调全局最多两个执行租约；缺少Redis的数据库环境禁止启动付费任务。任务保留7天，独立于对话会话的2小时过期规则。

一份简历包含一条职业概况向量及完整经历原文字段的分段向量，不只截取开头。每段最长1500字符、重叠150字符，记录路径和Unicode字符偏移；姓名、联系信息和年龄性别婚育等内容等长遮盖。每20段以内调用一次向量接口，成功后先保存分片回执，再写入搜索索引。搜索失败后可启动新任务复用已保存向量，不重复付费。

每批生成前后、写搜索前重新检查当前团队、角色、简历权限和行版本。简历更新后旧版本不再计为完成，删除后回执不可访问；搜索命中仍须从业务库重验当前权限和版本才能展示或交给对话模型。服务重启遇到已发出、却没有持久向量回执的付费批次会标记`uncertain`并停止，提示人工核对，防止盲目重复调用。任务错误可通过GET的`message`查看。

## 七日消费清理

接口：`POST /api/internal/ai-usage/cleanup`，也支持带相同请求头的GET。每批最多5000条，`has_more=true`时继续调用。

后端环境变量`GOODHR_AI_USAGE_CLEANUP_TOKEN`必须配置至少32位随机密钥。请求使用`Authorization: Bearer ...`或`X-Cleanup-Token`；URL参数、普通登录态和Cookie都不能替代密钥。接口返回`Cache-Control: no-store`。

每次仅清理早于当前时间减7×24小时的负向`ai_usage`消费明细。汇总与删除在同一事务内完成：先按北京时间日期将金额和数量写入`ai_usage_daily`，再永久删除对应调用明细。失败整体回滚，并发调用和重复调用不会重复累计。

不删除充值、赠送、管理员调整、退款及返还流水，不修改用户余额或`ai_wallet_lots`分笔资金。未完成分笔账本初始化的账号不清理，并明确返回`blocked_count`和`has_more=true`；脚本遇到阻塞立即失败，必须先核对0092账本迁移，不能将遗留消费当作已经清完。清理接口不会重新执行历史资金迁移。日汇总不保存用户、模型、Token或简历正文，永久保留金额与数量；月度和累计消费统计合并日汇总与保留明细。已汇总的历史按完整北京时间日期查询，无法恢复任意小时的调用明细。

需要迁移：`0100_ai_usage_daily_retention.sql`。迁移只建日汇总表与消费清理索引；旧程序不能读取该日汇总，清理启用后的回滚须带上日汇总兼容实现，不能直接换回只统计明细的旧版本。

## 每日任务配置

代码交付不代表服务器定时任务已经配置。正式部署完成并验证迁移后，在宝塔计划任务里添加每日Shell任务，建议北京时间03:10运行。

使用`goodhr5/scripts/cleanup-ai-usage.sh`，需要Bash、curl和Python3。把公开站点根地址及清理密钥保存在服务器受限的环境配置文件中（权限600），由任务加载后执行脚本。不要把密钥写进任务标题、URL、命令行参数或公共日志。后端与任务必须使用同一密钥。

```bash
# 下列路径是服务器部署示例，需改成实际路径；密钥保存在环境配置文件，不写进本说明。
set -a
source /etc/goodhr/ai-usage-cleanup.env
set +a
bash /opt/goodhr/goodhr5/scripts/cleanup-ai-usage.sh
```

脚本会按`has_more`继续清理，最多1000批；返回失败时计划任务应记录失败并提示核对，不宣称清理成功。单次手工调用也可以用curl从标准输入读取含请求头的配置，避免密钥进入进程命令参数。

## 验证范围

自动测试使用合成向量上游与内存账本；PostgreSQL事务用例只在明确配置回环地址、名称以`_test`结尾的`GOODHR_RECHARGE_TEST_DSN`时运行。真实模型渠道、生产迁移、宝塔每日任务仍须单独验证，不能以模拟上游测试代替。
