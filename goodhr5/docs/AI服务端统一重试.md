# AI 服务端统一重试

2026-11-15 按用户修正后的要求实施。上一版本地 AI 层改动已通过 Git 撤回；本次不修改本地程序或浏览器 Worker。

## 调用规则

统一入口是 `cloud/backend/internal/httpapi/ai_request.go` 的 `doServerAIRequest`。

服务器向上游发起首次请求，失败后额外重试三次，每轮最多四次。成功立即结束。网络中断、HTTP 408/429/5xx、空回复、普通响应或 SSE 协议中的坏 JSON、需要 JSON 输出时的非法模型正文、坏工具参数 JSON 均在此处理。

输出要求从请求的 `response_format` 或固定 system/developer 合同识别，不能由候选人原文或聊天资料更改。普通文字回复与 AI 连通性测试保留文字输出；JSON 事件流按每行一个 JSON 对象检查。评分、简历字段等业务含义仍由原有业务代码读取，本入口只处理通用返回与 JSON 语法。

服务器先收齐响应并完成格式校验，再把最终成功的内容交回调用方，包括 SSE。因此流式内容会在服务器完整校验后交付，坏尝试的半段内容不会提前泄漏给本地，也不会依靠本地判错再重发。

兼容代理、云端文字请求、附件解析、招聘助手、推荐 JSON、向量与独立精排共用该入口。服务器内部请求本站兼容代理时不重复套重试，避免四乘四次请求。招聘助手本身对业务合同和工具参数的纠错机制保持原有职责。

## 停止与旧客户端

- 401/402/403 等账号、余额、权限及明确请求配置错误不重试。
- 用户取消、任务总时限到达、当前权限或已引用候选人版本失效立即停止。后台助手每次重发前复核当前任务及引用。
- 重试前分别等待至少 500 毫秒、1 秒、1.5 秒，上游更长的 `Retry-After` 会被遵守，等待可取消。
- 上游四次预算用完，兼容代理返回 HTTP 422 与 `AI_RETRY_EXHAUSTED`。现有客户端不会把它当成 5xx/429 再请求三轮，因此无需升级客户端来获得服务器重试。
- `X-GoodHR-AI-Attempts` 表示本次实际完成的上游尝试次数。诊断继续记录真实上游 HTTP 状态，不能用客户端收到的 422 冒充供应商原始状态。

## 费用与日志

无效 JSON 也可能已经产生费用。每次尝试拿到可信 usage 后都沿用原钱包逐笔记账，最终回执合并所有已确认费用。有任何一次费用未知时，总金额仍标记为未确认，不用后续成功掩盖未知费用。本地账本写入失败立即结束，不靠再次调用模型修复。

公共日志只记录尝试次数、状态和固定错误类别，不记录密钥、简历或完整模型原文。

## 验证

验证使用本地合成上游，未调用真实付费 AI、生产数据库或候选人聊天：

- 一次客户端请求中前三次坏 JSON、第四次成功，普通与 SSE 都只交付最后有效结果。
- 四次全部失败后，旧客户端不会叠加重试到十二次。
- 逐次扣费与汇总回执一致，未知费用不被覆盖。
- 取消、账号错误、工具 JSON、输出协议识别、任务权限复核及旧诊断协议回归。
- 云端完整 `go test ./...`、重点用例 `-race`，以及 Linux amd64/arm64 后端编译。
- Git 核对 `local-agent-go-new` 与修改前提交 `5761372e` 完全一致；本次不涉及 Windows 或 Mac 客户端改动，也不重新打包客户端。
