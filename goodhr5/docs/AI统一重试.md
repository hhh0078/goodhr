# AI 统一重试

2026-11-15 确认：首次调用失败后额外重试三次，每个模型步骤最多请求四次，成功立即结束。

## 实现位置

- 本地程序及自动回复服务器：`local-agent-go-new/internal/integration/ai/retry.go` 的 `runAIRequest`、`chatResult`。
- 云端：`cloud/backend/internal/httpapi/ai_retry.go` 的 `retryAI`。
- 两个独立 Go 模块使用相同规则；业务流程只调用原有 AI 能力，不自行增加网络或 JSON 重试循环。
- 透明的 `CompatibleChat` 转发层不再次重试。模型输出格式由拥有该合同的 AI 能力校验，避免一次调用变成四乘四次请求，也避免重新发送部分 SSE 内容。

## 覆盖范围

本地公共能力覆盖基础预分析、文字及图片评分、回复生成、简历解析、简历摘要、图片转录、在线资料识别、推荐报告、标准工具调用。云端覆盖文字及其调用方提供的字段校验、附件识别、助手 JSON 事件、推荐合同、向量和独立精排。

重试包含网络故障、单次 HTTP 等待超时、HTTP 408/429/5xx、流中断、响应为空、JSON 不合格和当前合同要求的字段校验失败。网络与解析故障共用四次预算，不能各用一套次数。每次重发保留原有固定 system 消息与动态 user 数据分离。

用户取消、调用方总时限到达、密钥无效、余额不足、权限或请求配置错误立即结束。明确判定材料不是简历属于有效结果，不因它再调用模型。云端账本写入失败也立即结束，重新请求模型无法修复本地账本。

第一次、第二次、第三次重试前分别等待至少 500 毫秒、1 秒、1.5 秒。上游提供更长的 `Retry-After` 时遵守该要求；等待中支持取消。每次请求仍受调用方总时限限制。

## 结果与费用

- 本地每次 HTTP 尝试仍由原费用观察器独立报告费用，不覆盖之前的已扣费或费用未知状态。
- 云端继续校验真实用量后逐笔扣费，不把缺失用量当成免费成功；未知上游费用不能伪造金额。
- 失败尝试的助手事件不交给业务执行。工具参数 JSON 在公共 AI 边界验证，实际发送消息等业务动作不放入模型重试回调。
- 流式评分第一次完整可用时仍立即交付；尾部补读重试不重复触发评分回调，也不能改写已经交付的评分。完整简历字段可由最终成功的响应补齐。
- 推荐模型步骤耗尽预算后，保留原有单候选人失败与部分结果处理；外层不重跑已经成功的整条付费管线。后台持久任务的恢复轮次仍属于独立业务机制。
- 公共日志记录操作、尝试次数和错误类别，不打印模型原文、简历正文或密钥。

## 平台与验证

此次修改为公共 Go 的 HTTP、上下文与 JSON 处理，没有新增系统专属调用。Windows x64、macOS Apple Silicon、macOS Intel 共用上述同一实现；无需分别增加平台文件。

验证使用本地 HTTP 替身，覆盖混合故障共享预算、连续失败上限、第四次成功、账号错误、取消、限流等待、字段校验、逐次费用回执、失败工具事件隔离、每次重试前撤权检查、早评分与尾部补读。不调用真实付费 AI，不发送候选人消息。

交叉编译目标：`windows/amd64`、`darwin/arm64`、`darwin/amd64` 的 `cmd/goodhr-local-agent`；`linux/amd64`、`linux/arm64` 的 `cmd/goodhr-auto-reply-server`，使用 `CGO_ENABLED=0`。编译通过不能代替三个桌面目标的安装、原生依赖与实际模型运行验证；本次不重新打包或安装客户端。
