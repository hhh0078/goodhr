# 自动回复随后端启动

原弹框的“本地状态暂时没读到”掩盖了真实错误：客户端正常连接，云端未启动独立执行服务。前端现保留接口的实际错误，不再统一要求检查客户端版本。

## 默认部署

未设置 `GOODHR_AUTO_REPLY_RUNTIME_URL` 时，普通 `goodhr-server` 进程直接托管已有云端自动回复模块，共用现有容器和监听端口，不新增服务。公共入口为 `local-agent-go-new/cloudruntime`；业务编排、设备命令、发送幂等和权威 PostgreSQL 数据仍复用原实现，本机仅执行既有浏览器命令。

启动时在进程内生成内部服务凭证，供已验证的代理和内部事务接口共同使用，不写入镜像或日志。已提供的凭证保留。附件默认存放于后台日志目录旁的 `auto-reply/files` 子目录（正式环境为 `/app/logs/auto-reply/files`），复用既有持久卷，目录权限0700，不置于公开 uploads。可继续通过 `GOODHR_AUTO_REPLY_FILES_DIR` 指定绝对私有路径。升级及回退不得把此目录当成日志缓存删除。

显式配置外部执行地址时保留旧部署模式，不再启动第二套编排。停止进程时取消流程并等待已开始事务收尾。此变更不新增数据库迁移，不自动开启用户任务。

后端正式构建上下文调整到 goodhr5，根 `.dockerignore` 仅允许后端和所需自动回复源文件进入构建，排除运行数据与凭据。Go构建器使用官方1.25 Alpine，运行层保持官方Alpine3.22；发布来源校验同步覆盖新增输入。

## 验证

- 后端启动配置、私有目录、外部服务兼容、无效监听地址和相对目录回归通过。
- 独立测试数据库中，用真实编排处理器验证绑定设备可读取 idle 状态，未登录请求被拒绝；平台限制沿用既有回归。
- 现有云端编排测试通过；前端1366px和390px验证实际错误显示、恢复后可开启；既有账号确认启动回归通过。
- Windows amd64、macOS arm64/amd64的本地入口及Linux amd64/arm64后端编译通过。公共入口无系统调用，本地执行和安装代码未更改；未进行Windows安装或新的Mac安装测试。
- 正式发布仍走不可变候选、隔离数据库验收、完整回退验证和激活流程。真实招聘账号收发未验证，不以模拟测试代替真实发送验收。
