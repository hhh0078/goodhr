# 自动回复指定平台测试开放

2026-11-17，用户确认仅开放 BOSS直聘（boss）、猎聘企业端（liepin）和智联招聘（zhaopin）。猎聘猎头端（hliepin）、前程无忧（51job）、空平台及未知平台继续禁止开启。本轮交付范围为测试通过后推送主分支，不手动更改服务器配置或重新发布安装包。

## 行为与实现

- 前端 `lib/auto-reply-rollout.ts` 统一平台范围；岗位卡片与配置表单接收岗位平台，未开放平台不能从关闭切到开启，仍能查看、编辑及关闭历史配置。
- 工作台和岗位设置复用 `AutoReplyTestNotice`，显示“自动回复正在测试中，建议先添加作者微信后再使用，遇到问题可以及时联系作者。”，并链接到既有作者微信联系页。添加微信为建议，不作为启动前置条件。
- 后端 `auto_reply_rollout.go` 统一平台判断。配置保存、有效状态、岗位启动、执行快照均核对平台；保存事务在岗位行锁内读取真实平台，旧客户端不能绕过。
- 运行代理启动前读取本人岗位，核对客户端平台与真实岗位一致；不能通过把猎头端请求伪装成 BOSS 来调用执行服务。开始之外的状态、停止、回执继续保留；报告重试不重新发送聊天消息。
- 不恢复会员拦截，不修改套餐权益数据、余额检查、设备绑定、岗位归属、配置版本、消息身份或发送幂等。自动回复仍由服务器编排，本机协议和 Worker 没有改动。

## 验证与边界

后端平台策略、真实 PostgreSQL 配置事务、运行代理、快照及状态回归在本机专用 `_test` 库的独立 schema 执行；不使用生产数据。前端纯函数、既有工作台和桌面/手机界面使用合成账号及拦截的 API，没有向真实候选人发送消息。检查允许三平台、拒绝其余平台、伪造平台、旧配置编辑关闭、停止、作者链接和确认账号后的启动。

后端 `go test ./...`、专用 PostgreSQL 自动回复/岗位启动回归、前端 180 项纯函数测试、类型检查及 Webpack 生产构建通过。桌面/手机共 41 个界面场景通过，覆盖原有工作台与三平台测试开放；三处旧灰度断言更新后单独复查通过。已查看岗位设置以及岗位管理、简历库、猎头推荐和企业招聘截图。

## 运行服务前提

开放平台时的只读检查发现，生产后端未配置 `GOODHR_AUTO_REPLY_RUNTIME_URL` 和 `GOODHR_AUTO_REPLY_SERVICE_TOKEN`。开放界面和后端平台限制以后，实际运行仍需按既有云端自动回复架构部署执行服务并设置地址、服务凭证和附件目录；不能只去掉限制就宣称生产收发已经可用。缺少服务配置时沿用明确的 `RUNTIME_UNAVAILABLE` 错误，不回退成本机运行。
