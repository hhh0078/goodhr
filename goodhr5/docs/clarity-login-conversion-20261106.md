## 登录行为

表单增加未默认勾选的协议框及下划线链接。首次点击注册/登录时，未确认则弹出协议；无需滚到底部，点击“我已阅读”会自动继续原请求，不再要求第二次点击登录。主动预览只确认协议，不提交账号。取消保留输入，失败保留输入并允许重试；服务端原有协议校验和老账号补设密码规则保留。

## 统计口径

Clarity仅在正式官网和登录页加载；后台、未知路由、简历分享、面试邀请和诊断分享不加载回放。前端路由离开允许范围时停止回放，后台主区域另设遮盖。继续保留私人分享页原有的百度统计排除规则。输入内容沿用Clarity遮盖；协议新增统计用途及微软隐私说明。

| 事件 | 含义 |
| --- | --- |
| site_visit / login_view | 到达官网页面 / 登录页 |
| code_request / code_sent / code_failed | 请求验证码 / 发送接口成功 / 接口失败 |
| login_submit / validation_failed | 用户提交 / 表单字段校验未通过 |
| agreement_opened / agreement_accepted / agreement_cancelled | 打开 / 确认 / 取消协议 |
| register_success / login_success / login_failed | 注册成功 / 老用户登录成功 / 登录接口失败 |
| password_setup_required / password_setup_completed | 老账号需补密码 / 补设完成 |
| admin_entered | 后台真实读取账号成功，只记一次；通过百度事件统计，不在后台加载Clarity |

分类仅包含新老账号、验证码/密码登录方式和固定错误类型，不上传邮箱、验证码、密码、登录令牌及错误原文。验证码接口成功不等于邮件实际送达；前端成功事件须与服务器注册记录交叉核对，统计被拦截可能少记。后台到达只消费当前浏览器30分钟内的待到达标记。

建议分别查看新账号与老账号，并按来源、手机/电脑分组。Clarity初期以“登录页→验证码请求→发送接口成功→注册成功”观察注册路线；协议为可选分支，不能把未打开协议的正常注册算作流失。查看7至14天再判断，不能用百度新访客数直接当作注册意向人数。
