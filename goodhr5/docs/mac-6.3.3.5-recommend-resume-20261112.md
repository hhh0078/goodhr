# 推荐页续跑与Mac 6.3.3.5

2026-11-12。范围是主动打招呼的推荐列表断点；发送流程和智联详情点击代码未改，用户自行安装验证，不操作招聘页面。

## 原因与处理

- 本机6.3.3.4已经有断点和未完成人选队列，最近一次启动先回到了上次失败者。补处理失败者不等于从头扫描；现在岗位日志明确显示补处理、找到上次人选、锚点缺失和条件变化四种情况。
- 原恢复只检查已加载的名单，且要求锚点前的完整顺序不变。推荐系统换序或尚未加载到旧位置时，即使原人选仍可找到，也可能从头。
- 三个推荐平台显式启用身份恢复：无忧按唯一公开简历编号，BOSS和智联按现有稳定字段的联合摘要。身份重复不猜测；其他平台默认保持严格前缀规则。
- 未找到已保存者时，复用现有真实滚轮和列表推进方法继续加载，每次加载探测只读取一人的身份，名单核对每批最多20人。整次查找最多两分钟。确认稳定底部仍缺失才从头；读取、取消、断线或加载状态不明时保留断点并返回原因。
- 无忧和智联的搜索页保留原有前缀保护；智联搜索分页、筛选以及6.3.3.4的详情路径修复不变。平台初始化确认页面类型后才选择恢复规则。
- 补处理按身份识别同一个失败者，不再因新旧前缀不同把失败者当作缺失或累积重复记录。补处理完成后回原最新位置；推荐换序后失败者被移到更后面时，不用新行号跨过尚未扫描者。原前缀不变的尾部失败者修好后仍可推进。
- BOSS和智联恢复时同步还原锚点前同名同龄者的出现次数，保持后续卡片定位序号，不默认点第一个同名者。
- 沿用版本1/2的断点格式与原身份字段，不迁移或清空用户记录。账号、Profile、岗位和判断配置的隔离继续生效。

推荐换序时按当前名单中的锚点向后继续，锚点之前新插入的人选不保证在本轮补扫；无法可靠匹配锚点时仍从头。没有做招聘网站的安装运行或页面实测，不能将合成回归当作真机业务验收。
