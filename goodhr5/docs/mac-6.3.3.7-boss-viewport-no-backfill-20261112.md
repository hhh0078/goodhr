# BOSS当前可见位置起跑与Mac 6.3.3.7

2026-11-12。用户确认：BOSS不再追历史断点，从当前屏幕内第一位候选人开始；BOSS、智联、无忧都不回头补失败者，智联和无忧正常断点启动位置保持现有方式。

## 修改范围

- 新日志只有启动至候选人处理入口7条记录，不能据此完全确认每次滚轮的原因；旧代码确实会在历史锚点不在名单时向下加载，整次最多两分钟。
- BOSS移除历史断点能力，正式流程不会读取旧BOSS断点或失败队列。每个新运行时在首次带游标读取时，用现有Worker单元素查找获取卡片边界，在纵向列表二分定位首个与可用视口相交的卡片。沿用配置内页头、底栏避让范围，部分露出的首张卡片也属于当前起点。
- 起点定位只读，不移动焦点或滚动。为了保留同名同龄者的真实定位序号，向前只读姓名及年龄所需最小字段，每批至多20人；不分析、处理或联系这些人。原始行号保持不变。12秒内无法核实位置、列表未就绪、几何读取异常或位置变动时明确停止，不默认为第0人、不继续滚动追历史。
- 本轮后续批次沿原游标继续，不反复重置为启动位置。新建任务重新读取当前视口；如果平台因切岗而重置列表，就从切岗后实际看到的位置开始。
- 公共主动打招呼流程删除失败回补队列和跳回旧失败者的流程。每个人操作返回后，无论成功或失败都保存最新已尝试位置；失败仍按原日志和连续错误策略处理，不再冻结进度或安排回补。读取整批失败且尚未交付人选时，不推进未处理位置。
- 旧版本1/2记录的正常位置及条件摘要继续兼容，旧 `pending` 字段忽略，新记录不保存回补队列；用户既有失败日志、BOSS旧设置与浏览器资料不删除。已沟通状态的原生检查仍保留，BOSS从当前屏幕起跑可能再次分析屏幕里曾处理过的人，但不会因回补队列主动回头。
- 删除BOSS已不再需要的断点行为和地址追踪参数配置，保留其他平台既有正常断点能力。Go Browser接口仅补齐已有标准 `Find` 能力，Worker仍为原实现，没有新增平台分支、依赖或页面脚本注入。
