# 控制台交互式新手教程

## 用户体验

首次进入先邀请用户参加，支持开始教程或声明自己无需教程。跳过需完整输入 `让开，我不需要教程`，只保存当前账号在当前浏览器的选择。

教程分为五个阶段：准备本地程序、创建岗位、登录招聘平台、筛选并开始、看到筛选结果。顶部显示真实完成进度和剩余时间区间；安装下载速度、平台登录和 AI 等待会影响实际耗时，时间不是倒计时。

每个实际操作单独使用 Ant Design Tour 遮罩及说明，保留目标交互，完成后自动前进。提供上一步、稍后继续和遇到问题，不提供绕过业务检查的下一步。阶段完成给予简短鼓励与礼炮；减少动态效果设置会关闭礼炮。

先进入岗位管理并新建岗位，在岗位表单内确定招聘平台。实际保存后，高亮该岗位的“开始”；用户打开现有启动弹框，再高亮弹框里的“打开平台，并筛选条件”。复用该按钮实际打开对应平台，提醒切到招聘浏览器登录，并设置年龄、学历、地区等基础筛选条件。连续确认登录后，高亮同一弹框的“我已筛选好，立即开始”；用户确认筛选条件后才进入现有启动检查。教程不再使用顶部浏览器入口带路，不另造开窗按钮。

顶部加载保持图标占位和按钮文案不变，避免转圈结束后按钮变宽；遮罩也会观察实际目标尺寸变化并重新测量孔位。

打开请求与登录检测分开。只有弹框内实际打开成功才进入等待登录；同一弹框暂停恢复或断线重连只恢复连续检测，不重复开窗。刷新后弹框不持久化，旧开窗、登录、筛选或确认步骤统一回到原岗位“开始”，不自动开窗或运行。暂停、帮助、必要检查、上一步和换号会取消旧检测，旧响应不能推进当前教程。登录确认不等于平台筛选条件已设置，后者由用户在最终确认按钮声明；同一弹框已成功打开的平台，确认运行只核对当前页登录，不重新导航而覆盖条件。

关键词和AI选项在教学遮罩、帮助和岗位卡片中明确费用与适用场景。关键词基础筛选免费，适合单一、简单、按词匹配的条件；AI适合结合经历判断复杂、多项要求，需要有效会员，内置AI按用量扣GoodHR余额，自定义接口按服务商规则计费。关键词若配AI详情仍有AI调用费用。当前所有AI岗位仍沿用既有会员与余额启动检查；文案不改变默认模式、余额门槛或实际计费。

费用说明较长时，依据目标区域、顶部进度条及视口的真实空位决定气泡放在上方或下方，限制气泡总高度。标题和“上一步、稍后继续、遇到问题”固定可见，说明区可用真实滚轮或键盘滚动，不能靠遮住进度条或操作目标解决手机空间不足。

暂停时保留原岗位表单或开始弹框，可以继续用户正在填写或筛选的上下文；仅当这些教程弹框仍打开且没有必要检查时，把“继续教程 / 从头开始”入口放到其遮罩之上。普通暂停入口保持原层级，必要安装、连接等检查仍优先，不因抬高恢复入口而遮住必需操作。

平台登录配置复用 `lib/platform-login.ts`。标准配置继续支持 `auth.pages` 与 `public.pages`，公开规则的 `code` 可省略；旧版智联、猎聘企业端和猎头端没有 `public.pages` 时，只从现有 `auth.login_url_prefixes` 中的有效完整 HTTP(S) 地址生成公开登录前缀规则，不猜平台 URL、不修改云端配置。入口和登录成功仍沿用已有 `auth.pages`，不会把 `entry_url` 或 `logged_in_url_contains` 扩写成新的成功规则；缺少有效公开规则和旧登录前缀时继续阻止开窗并说明缺失原因。

登录判断先排除公开登录页，再判断已登录页面，避免 `auth.pages` 的泛域名命中把同域 `/login` 误当作成功。教程长轮询和岗位启动前的快速检查共用这个判断，必须离开登录页并连续确认后才能继续。

2026-10-16 真实猎聘猎头开窗复现：旧配置只列 `/login`，实际重定向到 `/account/login?backurl=...`，泛域名成功规则会误命中。补充只读取 URL pathname 完整登录段的保守排除；不读取 query/backurl 来判断登录段，不扩大任何登录成功规则，不修改平台配置或注入招聘页面。配置中的公开登录规则继续优先。

新手创建岗位按平台、名称、筛选模式、详情识别模式及适用条件逐项教学，每个字段都有独立遮罩。名称提示“到你选择的招聘平台‘岗位管理’复制完整岗位名称，保持一致”，用户可从平时使用的平台复制，不需要先由教程打开招聘浏览器。基础或详情任一使用 AI 时需岗位要求；关键词筛选需关键词；关键词配合 AI 详情时两项都需填写。原有完整新增和编辑表单继续用于普通使用，普通表单字段顺序保持原样。

平台选择沿用实际开放配置，未开放的平台不可选。新表单不预选 BOSS；选择和再次确认当前平台沿用 `form-field-completed` 事件，字段为 `platform` 并携带实际 `platformId`。草稿恢复保留实际平台和其他字段；平台后来关闭时在表单内要求重选，不静默切换平台或丢失草稿。已保存岗位的平台变为不可用时保留业务数据，重新引导创建可用岗位。旧版 `platform-select` 类型仅用于迁移，不再显示独立选择面板。

Windows 运行库未就绪时，遮罩指向原有下载和安装后检查区域，通过检查后再引导安装其余组件。启动岗位时区分检查中、检查失败和必要更新：高亮完整启动弹框，保留真实错误、进度和恢复按钮，岗位真正启动后才推进。

教程进行中组件状态也可能变化，不能只依赖首次进入时的检查。`useInteractiveOnboarding` 复用现有环境轮询，在组件安装状态变化时发布 `runtime-status-changed`；`RequiredRuntimeInstaller` 只接收当前 Agent 的状态，并让旧请求结果失效，及时显示同一份安装事实。这样组件从就绪变为缺失时，必要安装弹框和按钮会同步出现，避免教程已经转向安装步骤、弹框却仍以为组件就绪，遮罩一直等待不存在的目标。同步使用已有检测结果，不额外增加就绪用户的轮询。

## 状态和完成事实

- 界面进度：`lib/onboarding-state.ts` 使用版本 2 的账号隔离 localStorage；恢复页面后重新检测当前环境及岗位是否仍存在。
- 岗位草稿：`lib/onboarding-position-draft.ts` 只保存六项核心字段和可选岗位关联ID，按账号与岗位隔离；新建草稿保留原键，复核草稿单独保存，真实保存岗位成功后只清除对应草稿。
- 业务事件：`lib/onboarding-events.ts` 连接现有岗位保存、启动和筛选结果，通知异常不能影响业务操作。
- 云端事实：沿用 `/api/user-flow` 和现有存储结构，增加 `first_screening_result`，返回 `tutorial_completed`。历史已经完成的用户仍兼容；无需新建表。
- 真正完成：只有 AI 或关键词的终态筛选结果才算完成，接受或拒绝都可以；扫描数量、AI 分析中、关键词通过但仍需 AI 的预判断均不算完成。
- 本地程序：通用流程后台同步终态事实，只发送种类、阶段和终态标记，不上传候选人资料。同步有独立三秒上限，在途请求不叠加，失败允许后续真实结果重试，不阻塞招聘流程。

数据库事实优先于本机缓存。缓存不可用时当次仍可继续，并提示刷新可能无法保留位置；不同账号不会继承进度、草稿或请求去重。旧账号请求的迟到 401 不得清除新账号凭证。

保存岗位后点“上一步”进入 `position-edit`，高亮原岗位的真实编辑按钮，不能用帮助弹框替代回退。复核沿用 `formFromItem` 和原ID保存接口，其他配置保留；编辑中使用同一套核心字段遮罩，平台保持业务原有禁改规则，通过“确认使用此平台”继续。取消编辑返回复核入口，刷新可以恢复同岗位草稿，保存成功后再引导打开平台，不重复创建岗位。

进度条、帮助和暂停区均提供“从头开始”。确认后仅清除本轮微步骤和对应未保存草稿，保留实际岗位ID，重新邀请并复核原岗位。`reviewPosition` 记录复核，`replaying` 记录用户明确选择重走；即使云端已完成，显式重走也能刷新继续，但绝不清空云端完成事实。保存或启动在途不允许重置，运行中要求先由用户通过现有停止操作结束；重走不自动调用开窗、运行或停止。回退、重走与换号使旧检测轮次失效，迟到响应不能把同ID的新一轮教程推进。

帮助弹框保留“我再试试”，并直接提供“上一步”和“从头开始”，避免遮住底层操作后没有返回出口。

旧版版本 2 缓存若停在平台选择或登录、但尚无实际岗位，会迁移到岗位管理入口。已有岗位恢复和顶部开窗前都回读实际岗位，以真实 `platform_id` 为准；平台与缓存不同时清除旧登录事实并打开实际平台。实际岗位缺少或带有未知平台时不能回退到缓存平台开窗。教程活动中，顶部入口只在已有岗位的开窗或登录步骤接受请求；创建前的键盘触发也不能落入普通浏览器打开流程，暂停后恢复普通入口。

暂停后恢复会核对关联岗位仍存在且开启。岗位已删除或关闭时，说明原因并重新引导创建岗位，其余有效进度仍保留；不能留下指向已消失按钮的遮罩。

任务已在本地结束但尚无筛选结果时，“上一步”会重新读取本地终态，复用现有安全停止接口并回读云端岗位，确认云端已停止后才返回开始入口；同步失败保留当前节点并允许重试，不依赖可能滞后的云端 `running` 状态直接重复启动。

## 弹框协调

教程活动中以及稍后继续状态，暂停公告、普通更新、关注奖励和新用户福利自动弹框；退出教程后恢复普通规则。必要升级与强制组件安装仍执行现有检查，邀请完成后让出遮罩，必要处理结束自动继续教程。连接失败由教程当前步骤说明和帮助承接，避免两层遮罩争抢。

启动检查弹框按进度条实际底部避让，手机同步收缩可滚动正文，保留完整标题、原因和底部操作；仅教程活动时生效。遇到必要升级阻塞时，进度条降至必要弹框遮罩下方，检查完成后恢复。

遮罩目标使用控制台稳定的 `data-onboarding` 属性；等待弹框动画和目标出现后定位。菜单高亮整个真实菜单项；短窗口下将被正文裁切的字段滚入自身弹框的可视区域，捕获内部滚动并重新测量孔位，避免沿用旧坐标。窗口尺寸变化时重新定位。教程不向招聘网站注入脚本，不改变浏览器操作工具职责。

### 持久化预览（供人工验收）

当前人工入口是 `http://127.0.0.1:5174/login?next=%2Fadmin%3Flocal_port%3D43131`：前端 5174 直连真实 Go 后端 8085，招聘浏览器由宿主机独立真实 Agent 43131 打开，Worker 使用独立端口 39883。前端编译时固定真实端口，不会误探正在使用的生产 Agent 43129。

PostgreSQL 与 Redis 使用 `goodhr-onboarding-preview` 独立命名卷，账号、密码、岗位、完成记录与会话可以跨容器重启保留；不配置 SMTP，容器设置 `restart: unless-stopped`。所有对外端口绑定 127.0.0.1。5173/8084 属于其他测试环境，不要混用或删除命名卷。

Windows 从仓库根目录运行以下命令。隔离脚本只复制已安装的 Agent、Worker、浏览器与 OCR 组件；Node 只读复用，不下载依赖，不复制生产数据库、Cookie、Token 或招聘平台 Profile。默认将全部新增运行库、账号资料、日志和临时文件放到 `D:\goodhr-onboarding-real-preview`，不会改动生产 Agent 43129 的进程或数据。脚本需要现有 Windows 安装目录 `D:\GoodHRLocalAgent`；Mac 不执行此脚本，仍需单独验证对应安装包。

```powershell

python ./goodhr5/scripts/release_guard.py image --image goodhr-onboarding-frontend:local --kind frontend
```
