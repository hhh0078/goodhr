# 公众号免密登录

本次默认展示现有公众号二维码。用户扫码后向公众号发送页面上的四位数字（也兼容 `验证码 四位数字`），微信回调确认后，原页面自动取得登录态并跳转。首次注册仍需阅读并同意现有协议；已经同意的老账号自动进入。本次不增加手机号、短信或微信账号密码。

邮箱验证码、邮箱密码及找回密码继续使用原接口。已经绑定公众号的邮箱账号复用原账号及其岗位、会员、余额等归属；未绑定的邮箱账号不猜测合并，应继续通过邮箱登录。首次微信注册不需要邮箱和密码，数据库沿用现有账号关联键，以随机内部标识关联业务数据，界面显示“微信用户”。内部标识不是收件地址，不能走邮箱验证码、密码或重置密码入口。

## 接口及配置

- `POST /api/auth/wechat/create`：生成五分钟有效的四位登录码和独占随机凭据。重新生成可携带 `previous_ticket`，仅在新码成功创建后原子作废旧码和旧凭据，失败保留原码。登录生成独立按来源IP限制60次/10分钟，不与关注绑定的5次配额共用；错码仍限制5次/10分钟。
- `POST /api/auth/wechat/poll`：仅凭256位页面随机凭据查询或一次领取登录态。返回等待、过期、待同意协议或现有登录结果；短码不能领取登录态。
- `/api/wechat-official/callback`：复用现有签名、加解密和接收人校验。`验证码 四位数字`独立处理（兼容过渡期未过期八位旧码及中英文冒号）；原四位绑定码和关注奖励流程保留。首个微信认领后不能被另一微信覆盖，重复回调不会重复创建账号。
- `system.wechat_official_account` 可选 `login_enabled` 单独控制登录，未设置时在配置记录启用且回调配置完整时可用。原 `enabled` 仍控制关注奖励，不因启用登录而开启奖励。
- 临时挑战复用认证Redis，连接错误不静默转内存。仅未配置Redis的开发模式使用内存；页面串行轮询、请求超时中止，离开或切换入口后不继续接收旧结果。

新增迁移 `0125_wechat_login_identities.sql` 只新增身份关联表，表和字段都有中文备注。微信身份指纹持续关联原账号，取消关注不会删除账号或业务数据。账号创建在微信确认且协议同意后执行，同一身份的事务锁避免并发重复注册。临时原始OpenID随挑战到期或消费清除，持久新表只保存指纹。

免邮箱账号跳过会员、余额和岗位邮件提醒，不因不可投递地址阻断岗位结束。自动邮件筛选和手工群发排除内部标识；自动回复接手接口明确返回未发邮件并指向工作台，不伪报发送成功。普通邮箱的提醒继续沿用原有行为。
