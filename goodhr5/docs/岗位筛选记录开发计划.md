## 两轮语义

第一轮是列表卡片预筛；第二轮是详情评分。关键词判断也保存实际结果，分数为空；未执行、运行中、失败、取消与通过/不通过分别表达。第一轮拒绝后，第二轮记录未执行及原因。达到招呼上限或停止时，即使主循环尚未消费，已经真正执行的并发预筛结果也必须留存。

时间存 UTC RFC3339，界面按用户本地时区显示。每轮分别保存开始与完成时间，耗时从调用前保存running开始，至分数和原因可用为止，包含该次本地落盘开销；不用相邻日志的时间差，也不等待后台完整结构化简历输出。界面以秒展示实际毫秒值，零分和不足一毫秒的零耗时是有效值；未执行时间和耗时为 null。

每次候选人筛选生成新的 UUID `attempt_id`；后续轮次及断网重传沿用此编号。平台指纹仅为快照，不能作为跨次筛选合并键。不强制先创建云端简历，也不受结构化简历上传开关影响。历史未采集的信息不补造。

## 跨端接口

`GET/POST /api/positions/{position_id}/screening-records`，使用已有正常登录会话，禁止插件有限会话。写入与读取都核对当前账号、租户和本人岗位，payload 不允许指定 owner 或 tenant。

POST 为单份完整快照，所有快照本地落盘后才允许异步上传：

```json
{
  "attempt_id": "00000000-0000-4000-8000-000000000002",
  "task_id": "local-task-id",
  "platform_id": "boss",
  "platform_candidate_id": "",
  "candidate_key": "本次抓取的稳定候选人指纹",
  "candidate_name": "合成人选",
  "occurred_at": "2026-10-26T06:00:00Z",
  "revision": 2,
  "completed": false,
  "termination_reason": "",
  "first": {
    "kind": "ai",
    "status": "passed",
    "accepted": true,
    "score": 75,
    "threshold": 60,
    "reason": "有相关工作经历",
    "started_at": "2026-10-26T06:00:00Z",
    "finished_at": "2026-10-26T06:00:02Z",
    "duration_ms": 2000
  },
  "second": {
    "kind": "none",
    "status": "not_executed",
    "accepted": null,
    "score": null,
    "threshold": null,
    "reason": "尚未进入详情评分",
    "started_at": null,
    "finished_at": null,
    "duration_ms": null
  }
}
```

`kind` 为 `ai/keyword/none`，`status` 为 `not_executed/running/passed/rejected/failed/cancelled`。AI 通过或拒绝必须有真实分数、结果及时间；关键词分数必须为 null。score/threshold 是 0–100 的有限数字。未执行不写伪造时间或分数，原因保留；结束快照不能还有 running 阶段。每轮原因最多 16000 字，POST 请求体最多 256 KiB。

云端唯一键为 `(tenant_id, position_id, attempt_id)`，并校验原始 task/platform/candidate_key/occurred_at 不被换绑。相同版本和内容重传返回原记录；相同版本内容不同返回 409；旧版本到达时不覆盖新版本，返回当前 revision。响应为 `{ok:true,id:"...",revision:2}`。本地只在云端确认对应版本后更新已同步版本，上传期间的新本地结果不能被旧回执清除。

GET 支持 `page`，`page_size` 固定 20，`first_score_min/first_score_max`、`second_score_min/second_score_max`、`first_started_from/first_started_to`、`second_started_from/second_started_to`。分数上下限包含端点，时间范围起点包含、终点不包含；只填某一边同样有效。多个条件同时满足才命中，null 不当成零分参与比较。默认 `occurred_at DESC, id DESC`。所有筛选和分页由数据库执行。

响应 `{ok:true,records:[...],total:0,page:1,page_size:20}`，每项在 POST 快照字段外包含 `id/position_id/created_at/updated_at`，不返回内部租户/owner字段。前端只读，不依赖 Local Agent 在线，不触发岗位启动或任何 AI 请求。
