# 每日运行日志清理与数据库备份

用户于2026-11-11确认：北京时间每天05:00清理七天以前的运行日志，每天06:00完整备份数据库，仅保留本每日任务最近七份新备份。既有发布备份继续保留。

## 运行日志

后端实际HTTP入口调用 `Server.StartDailyMaintenance`，通过现有 `chinaLocation` 计算下一次05:00。只构造服务或加载路由不会启动清理，也不在重启时立即删除历史数据。

`position_log_retention.go` 复用已有PostgreSQL日志存储，每批最多5000条，只删除 `position_logs.created_at` 严格早于本轮执行时间减七天的记录。七天边界和更新记录保留；分享快照、全站统计表、资金流水和其他业务表不删除。运行日志列表及直接从原始日志计算的历史岗位计数，只能再查看保留期内的数据。

清理使用独立64位事务级咨询锁，避免与岗位写入的32位锁冲突；多实例只允许一轮执行。每批独立提交，跳过正在被锁定的行，单批最多30秒、整轮最多30分钟；失败记录已完成数量，不会误称未完成记录已删除。取消或连接退出后数据库自动释放锁，次日继续按固定保留期处理。普通删除让数据库复用空间，不执行阻塞整表的 `VACUUM FULL`，不承诺立即缩小宿主文件。

后端日志会记录下一次北京时间执行时间，以及每轮删除数量、保留界线、耗时和失败原因，不打印日志正文或连接凭据。

## 每日数据库备份

宝塔计划任务“GoodHR每日数据库备份”使用服务器北京时间每天06:00调用 `scripts/daily-database-backup.py`。入口持源码共享锁，防止自动部署在导入脚本时更新文件；脚本另持自己的非阻塞文件锁，禁止手动与定时备份重叠。

仅写入 `/www/backup/database/goodhr-production-daily`，目录0700，归档、清单和结果记录0600。由当前正式后端实际DSN确认库名，校验其本机端口确实映射到运行中的共享 `postgres` 容器；用该容器内同版本 `pg_dump -Fc` 完整备份，再用 `pg_restore --list` 离线核验TOC并计算整份SHA256。密码不进入命令、URL、清单或日志。

新归档和全部保留候选均核验成功后，才按文件名UTC时间保留最近七份，精确删除本任务同主机、同数据库、带已验证清单的更旧归档及配对清单。小型执行结果审计继续保留；既有发布备份、其他数据库、其他目录及未登记文件不参与轮换。生成或校验失败时不轮换旧备份，仅清理本轮未完成的 `.partial` 文件；完整归档已经落盘但清单保存失败时保留该归档用于排错。

备份前为Docker分区预留3GiB、上一份最大备份大小及256MiB余量，空间不足时保留旧备份并明确失败。每日备份不切换容器、不恢复或改写数据库，不修改原每分钟自动部署任务。首次启用前执行一次真实备份校验，为第一次05:00清理保留近期完整备份。
