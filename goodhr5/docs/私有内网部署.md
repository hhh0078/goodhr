# GoodHR 私有内网部署

私有系统的网页、API、数据库、插件业务和组件下载均使用企业内网。招聘网站仍需要联网；AI 使用个人配置中填写的内网 OpenAI 兼容接口。只有后端明确设置 `GOODHR_DEPLOYMENT_MODE=private` 才开放自定义 AI 启动，不影响线上版本。

## 部署 Windows 或 Mac 主机

安装并启动 Docker Desktop，并准备 Python 3（运行仓库现有镜像来源检查工具；Windows 需可执行 `python`，Mac 需可执行 `python3`）。Windows 使用 Linux 容器；Mac 的 Apple Silicon 和 Intel 均使用相同 Compose 文件，Docker 自动选择对应架构。

复制 `goodhr5/environments/private.env.example` 为 `private.env`，修改以下值：

- `GOODHR_PUBLIC_BASE_URL`：稳定的内网 HTTPS 地址，例如 `https://192.168.1.100:8443`。建议在路由器为主机保留固定 IP；也支持内网域名。
- `GOODHR_HTTPS_PORT`：与上述地址的端口一致，不写端口时填写443。
- `GOODHR_SUPER_ADMINS`：一个管理员邮箱，用作账号标识，不需要向公网发送邮件。
- `GOODHR_PRIVATE_ADMIN_PASSWORD`：首次初始化密码。已有密码不会因重启而被覆盖。
- `GOODHR_DB_PASSWORD`：至少24位随机英文字母和数字。数据库不会映射到宿主机端口。

在 `goodhr5` 目录运行：

```powershell
# Windows PowerShell
.\scripts\deploy-private.ps1
```

```sh
# macOS，使用系统自带 zsh
zsh scripts/deploy-private.sh
```

首次准备需要联网：拉取干净官方镜像、构建程序和插件，后端从 GoodHR 当前已发布清单下载 Windows x64、Mac Apple、Mac Intel 的 Node、Camoufox、清单中其他组件以及 Windows VC++ 运行库。这里的“最新版”指 GoodHR 已验证并发布的兼容版本，不盲目替换为上游未经测试的新版本。

公网组件源必须已部署本次新增的 `/api/system/deployment-assets` 接口。清单缺失、平台缺少、下载失败或 SHA256 不一致时，准备阶段明确失败，不会把未完成文件标成可用。检查后端日志后重试即可，旧文件不会被删除。VC++ 官方安装器首次通过 HTTPS 下载并计算摘要，此后随缓存一起校验。

组件持久保存到 `goodhr5/private-data/assets`。完整准备后，正常重启不会重新访问公网；会重新核对缓存文件摘要。需要更新组件时，在可联网环境将 `GOODHR_PRIVATE_REFRESH_ASSETS=1`，重建后端，准备成功后恢复为0。不要长期保持1。

## 信任一次内网证书

Caddy 为填写的内网 IP/域名自动签发证书，CA 保存在 `private-data/caddy`。不申请公网证书。启动脚本会导出公开根证书 `private-data/GoodHR-private-root.crt`，只将这一个公开文件分发给员工，不分发整个 Caddy 目录或任何私钥。

每台使用电脑首次信任该证书：

```powershell
# Windows 当前用户证书库；企业也可通过统一设备策略分发
certutil -user -addstore Root .\GoodHR-private-root.crt
```

```sh
# macOS 系统证书库，需要本机管理员密码
sudo security add-trusted-cert -d -r trustRoot -k /Library/Keychains/System.keychain ./GoodHR-private-root.crt
```

重启浏览器和 GoodHR 本地程序，再访问配置的内网 HTTPS 地址。Chrome/Edge 若询问本地网络或本机连接权限，允许当前 GoodHR 站点。Firefox 需确认其信任系统证书，或在 Firefox 证书设置中导入根证书。

内网 HTTP 页面在新版 Chrome/Edge 中可能无法连接本机程序；本方案使用受信的内网 HTTPS。不要通过关闭证书校验或关闭浏览器安全检查解决连接问题。更换 IP/端口后需同步配置并重新打包客户端；保留同一 CA 目录则无需重新信任根证书。

## 打包并登记私有本地程序

Windows 在 Windows 上打包，Mac 在 Mac 上打包；均复用正式打包流程，依赖继续使用现有国内 npm/Go 镜像。

```powershell
# Windows x64，版本号示例
.\local-agent-go-new\scripts\package-windows.ps1 -Version 6.4.0 private
```

```sh
# macOS，同一安装包包含 Apple Silicon 和 Intel 主程序及两套 Worker 原生依赖
zsh local-agent-go-new/scripts/package-release.sh 6.4.0 private
```

两种打包器都读取 `environments/private.env`，也可通过 `GOODHR_ENV_FILE` 指向另一份私有环境配置。私有包写入服务地址和 `DefaultDeploymentMode=private`，下载只允许服务同源，禁止跳转至公网；Mac/Windows 的公开版本策略保持不变。

私有客户端按服务地址隔离本机数据目录，不自动迁移或复用公网版本的登录和浏览器资料。手动指定 `GOODHR_DATA_DIR` 时应使用独立目录。本机端口仍为43129，同一电脑不要同时运行两个版本。

将本轮私有安装器和其 `build-info.json` 放到部署机，在 `goodhr5` 目录登记：

```sh
node scripts/register-private-client.mjs environments/private.env /路径/安装器.exe /路径/build-info.json win 6.4.0
node scripts/register-private-client.mjs environments/private.env /路径/安装器.pkg /路径/build-info.json mac 6.4.0
```

Windows 构建信息位于本轮 release 发布目录；Mac 位于 `release/GoodHR Local Agent.app/Contents/MacOS/build-info.json`。登记工具核对构建信息中的私有环境、版本和地址，并计算安装器 SHA256，复制到内网组件目录。

```sh
docker compose --env-file environments/private.env -f docker-compose.private.yml restart backend
```

重启后，内网下载页与更新检查使用这些私有安装器。未登记时不提供默认的公网程序，也不会误提示安装公网版本。更换地址后必须重打包再登记，避免客户端仍连接旧地址。

## 插件和 AI

部署脚本构建同版本的 Chrome/Firefox 插件并默认写入内网地址，下载页、插件更新和托管浏览器的临时 Firefox 通道均从内网获取。Firefox 未签名包仍按现有临时加载方式使用，不冒充正式签名包。

插件工具栏设置页新增“GoodHR 服务地址”，支持 IP、域名和端口。连接新地址时只申请该站点的访问权限；切换前撤销旧站授权、退出账号并清除旧草稿和版本缓存。旧站授权尚未撤销时保留原地址，恢复旧站连接后重试。招聘页面没有新增业务写入或自动点击权限。

首次用管理员账号密码登录，进入“个人配置 → AI配置”，填写内网接口、模型和 Key。无需鉴权的模型填任意非空 Key 作为占位值。BOSS 详情分析需要支持图片的模型；后端容器与执行端都需能访问该模型地址，不要把模型地址写成容器自身的 localhost。

自定义 AI 启动不检查本站余额，仍检查地址和模型配置、账号归属、设备与运行冲突。原有自动回复灰度限制和 AI 招聘助手/向量检索的独立配置要求继续保留。需要员工自助注册或邮件通知时，可配置企业内网 SMTP；不默认依赖公网邮箱或微信登录。

## 数据保护与验证

- PostgreSQL、Redis、上传文件和自动回复文件使用独立持久卷；组件、客户端安装器和 CA 使用 `private-data`。备份时同时保存环境文件、持久卷和 `private-data`，不要执行 `down -v` 或全局 Docker prune。
- CA 私钥、用户数据和密码不会进入镜像构建上下文或 Git。部署默认关闭第三方页面统计。
- 服务启动成功后，验证内网管理员登录、保存 AI、插件登录与查重、三个客户端目标的组件安装与岗位启动。阻断 GoodHR 公网和组件公网域名后，重启后端并再次下载组件，确认没有公网回退。
- 代码已提供内网 AI/零余额启动、线上限制不变、缓存摘要失败与离线重启、下载同源限制等自动化测试。当前验证记录见本轮交付说明；交叉编译不等于 Windows/Intel Mac 的安装或招聘网站实际运行验收。

浏览器限制依据：[Chrome Local Network Access](https://developer.chrome.com/docs/modern-web-guidance/guides/security/local-network-access)。证书方案依据：[Caddy 内部 TLS](https://caddyserver.com/docs/caddyfile/directives/tls)。
