# 管理员系统统计

本文说明全站统计入口、时间口径、数据来源、采集边界和验证方法。

## 入口与时间

- 入口：超级管理员的「系统管理 → 系统统计」，路由 `/admin/statistics`。
- 所有期间指标默认北京时间今天，支持昨天、近7天、近30天和自定义自然日，单次最多366天。
- 单日筛选时，消费曲线显示截至该日的近7天，每天一个点；多日筛选时按选中日期每天汇总。无消费日期补零，今天标注截至当前。
- 当前总量、当前余额、当前有效绑定版本是查询时快照，不是所选日期结束时的历史快照。
- 只展示全站汇总，不显示个人排行、邮箱名单或候选人详情。导出同样只包含汇总。

## 指标口径

| 区域 | 口径 |
| --- | --- |
| AI消费、扣费笔数与曲线 | 权威负数 `ai_usage` 流水与 `ai_usage_daily` 已清理日汇总合并，不含充值、赠送和退款。整数0.0001元运算，接口金额为字符串。 |
| 收款、退款、净收款 | 成功订单按 `paid_at`，成功退款按 `completed_at`；会员和AI充值均属于实付收款，AI充值另外单列。净收款为收款减退款，不与用户钱包消费相加。 |
| 本金、赠送与人工调整 | 新账本有明确资金拆分时展示。赠送使用实际 `bonus_change_units`，不套用每人固定赠送估算；退款失败的预扣返还不算新增赠送。当前本金为实际总余额减赠送余额。 |
| 活跃用户与团队 | 期间发生登录、筛选、AI实际扣费或启动本地程序的去重用户；团队按这些用户当前所属团队去重。不会用最近一次登录时间伪造完整历史日活。 |
| 次日和7日留存 | 取消长期统计明细后，无法用最近一次登录可靠还原历史每天的活动，暂不展示留存率，显示横线并说明原因。 |
| 新用户漏斗 | 所选日期注册的同一批用户截至查询时，按已有流程步骤依次完成的去重人数。依次为注册、启动本地程序、安装组件、创建岗位、平台登录、启动岗位、处理首份简历、首次打招呼成功。不是用每天各步骤操作次数拼成转化率，也不把教程完成等同于打招呼成功。 |
| 卡点 | 上述注册批次当前 `blocked` 状态的步骤分布，不展示具体个人。 |
| 处理简历 | 复用官网的 `system_daily_stats` 已处理计数。该计数沿用既有本地去重后上报接口，不表示独立候选人总数。 |
| 筛选 | 读取仍保留的岗位筛选记录及其当前修订，初筛/复筛完成、通过、失败和耗时分别汇总；不再额外复制每次attempt的统计明细。 |
| 成功打招呼 | 读取岗位仍保存的当前北京时间日累计值，跨天后的旧日数字不再由统计明细补存，历史期间可能不完整。 |
| 简历 | 新增入库主体数量，多个来源不重复计入，来源口径复用简历库的空来源归自动采集规则；内置瓜瓜不计入。 |
| 推荐、招聘与面试 | 新增推荐关系、跟进事件、新启用招聘流程分别计数；面试按排期日期且排除已取消场次。入职只统计已记录入职日、完成流程且阶段为hired的记录。 |
| 运行异常 | 只计已上报 `is_error=true` 的运行事件，按稳定事件号去重。普通退出及正常停止不直接当成异常。 |
| 版本与绑定 | 每个有效绑定账号只选最近的一条版本记录。绑定不等于在线，运行中岗位也是数据库记录的当前状态。 |

## 数据采集和历史边界

用户于2026-11-13明确取消整套逐条统计事实记录。迁移 `0126_retire_system_stat_facts.sql` 关闭全部五个采集触发器和采集函数，移除旧明细表及索引；同名入口改为普通只读视图，即时读取已有业务数据，物理存储为零，不创建新的统计明细或后台回填任务。历史迁移0124保持原样，仅按迁移账本顺序升级，不重新执行旧迁移重建明细表。

视图保留旧版查询兼容性，只投影现有登录时间、AI扣费、筛选记录、必要运行事件及岗位当前日招呼数据；正常过程事件不进入统计查询。原始业务表、钱包、资金流水和既有日汇总均不删除。界面仍只返回全站聚合，不展示个人记录。

已清理的筛选、异常和历史每天登录无法完整恢复，接口明确提示历史期间可能不完整，留存率不以0%代替未知。AI金额及扣费笔数继续合并权威流水与既有日账准确汇总；若日账没有模型、Token或资金拆分，不把缺失当作完整数字，模型分布仅包含仍有明细的部分。

已有简历、推荐、客户、招聘等业务数量仍按真实业务记录统计，沿用原业务去重和保留策略。升级前必须保留完整数据库备份；隔离验收仅对用户明确取消的统计投影允许退役，单独记录旧表行数、摘要及备份SHA，其他业务表和旧迁移账本仍完整核验，并实际验证旧前后端能读取兼容视图。

## 接口和验证

- `GET /api/admin/statistics?period=today`；自定义使用 `period=custom&start_date=YYYY-MM-DD&end_date=YYYY-MM-DD`。
- 复用超级管理员鉴权，拒绝插件会话、个人筛选、重复参数和未知参数；返回禁止缓存头。
- 各汇总、曲线和当前值在同一PostgreSQL只读可重复读事务内获取；读取失败显示错误和重试，不伪装成零。
- 合成界面测试复用 `tests/ui/admin-uniform-fixture.ts`，不操作真实业务账号或本地浏览器任务。
- 单测覆盖北京时间边界、金额精度、缺失值、CSV公式防护和访问权限；真实SQL在显式回环 `_test` 库的独立schema内覆盖全部迁移、零用户漏斗、日界线、重复事件、事务回滚、迁移重放、旧明细退役和视图零存储，并核对AI七日清理前后金额一致、缺失明细明确提示。
- 本次仅修改云端Go和Next.js，不修改本地程序或Worker，无本地程序安装包变更。

## 发布

合并代码不等于生产上线。云端上线仍需遵循《生产发布与回收.md》，为同一候选镜像准备隔离数据库兼容和完整回退证据后激活。统计采集触发器全部移除，原业务写入不变；无存储视图保留旧版统计SQL入口，不能恢复已取消的历史明细。正式发布前仍须完成候选及回退验收并保留备份。
