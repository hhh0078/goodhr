# 自动回复工作台日志与重复采集修复

本文说明紧凑工作台、独立运行日志和重复采集保护的实现与验证边界。

工作台将测试说明改成单行文字，启停、状态和带数量角标的待补充入口放在右侧。运行日志占主要区域，点击一条记录可查看阶段、耗时、具体设备错误或安全诊断。每次打开工作台时重新读取补充数量，有待办就自动打开独立补充弹框，也可手动打开。手机自然换行。

`0129_auto_reply_logs.sql` 新建 `auto_reply_logs`，按团队和登录成员隔离，在账号锁内保留最近1000条。稳定事件编号去重，更新不会复活已淘汰日志。来源外键保证候选人资料及权威事件删除后展示记录同时移除。迁移仅复制最近千条历史运行事件；旧版本可在新增表和触发器保留时回退运行。展示清理不删除聊天、采集意图、发送收据或权威运行事件，不能用展示日志判断是否需要再次发送。

2026-11-27 本次故障只读证据：李东春仍留有未完成采集意图；检查当前聊天和打开聊天交替返回 `ACTION_FAILED`，期间其他会话间歇成功。旧计数只记连续同类错误，被另一类错误和其他会话成功反复打断。历史日志仅保存固定安全提示，原始读取失败的底层原因无法从这些旧记录确定，不能将最后显示的“沟通岗位未匹配”直接当成李东春的失败原因。

公共流程现在按操作和稳定会话分别计错，同一会话三次处理失败即安全停止，保留待办供恢复。处理其他会话成功不会冲掉这个计数。BOSS检查“原窗口是否仍打开”时，明确已经换到其他姓名属于正常窗口变化；同名但原生编号不符继续拒绝操作。未修改消息、发送收据及未知发送结果的保护逻辑；启动前已有未读仍沿用已验证的持久采集恢复。

云端日志复用现有凭据脱敏。AI和已有业务诊断优先使用安全诊断；设备错误保留实际原因并限制长度。未分类业务异常不直接输出可能含私人正文的任意错误。旧记录没有保存的细节无法补造，页面会明确提示。

平台差异：本次公共错误策略运行于云端同一套Go流程；本地只修改 `internal/platform/boss/reply.go` 的只读窗口检查，不引入系统专属调用。Windows x64、macOS arm64、macOS amd64使用同一Go实现。macOS安装脚本分别编译两架构并分别安装对应Worker原生依赖，再生成通用安装包。Windows安装和Intel Mac真机运行需在对应设备继续验证，交叉编译不能替代安装验收。

验证包括隔离PostgreSQL的千条上限、账号隔离、更新幂等、来源删除、真实认证接口及错误脱敏；公共流程/平台/云端日志回归；1366px和390px工作台、独立弹框自动及手动打开。真实招聘页面只做标准只读定位检查，未为验收向候选人发送测试消息。具体编译、安装包和发布证据保存在本轮本机验收目录。
