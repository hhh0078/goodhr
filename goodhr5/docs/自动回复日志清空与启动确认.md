# 自动回复日志清空与启动确认

本文说明工作台日志清空、启动确认及支付提示的范围和验证方式。

运行日志右侧提供“清空日志”，二次确认后调用现有日志资源的 DELETE 方法，只删除当前登录账号的独立展示日志。允许没有连接本机或余额不足的账号手动清空。用户传入其他账号编号无效，未登录和插件凭证均不能清空；聊天、业务审计、发送去重账本与其他账号日志不受影响。清空后回到第一页，轮询重建以丢弃旧请求；运行期间产生的新日志继续展示，旧权威事件更新不会恢复已清空的展示记录。

每次真正开始自动回复前，现有“确认当前招聘账号”弹框都提示“开始时将会清空日志。”，确认按钮为“清空日志并开始”。取消不清空、不启动。先检查最新余额、招聘账号、本机绑定和运行组件，再清空并发出启动请求。启动用途的清空请求带 before_start=true，云端再次复查0.1元门槛；低余额或钱包读取失败不删除日志。清空接口失败或结果不完整时不会请求启动。清空成功后若启动本身失败，展示日志不恢复，页面显示具体错误，业务及发送账本仍保留。停止、打开工作台、查看补充和重试待办不自动清空。

支付前无法连接本机时，共用提示改为“请先下载本地程序、连接成功后才能支付。”，AI充值及现有订阅支付入口共用该文案；支付接口、金额与订单流程不变。

本轮仅修改云端前后端，无数据库迁移，不需要更换客户端安装包。验证包括真实本机隔离PostgreSQL认证路由、账号隔离、零余额手动清空、启动余额拦截、保留权威发送账本、重放不恢复、新日志可写，以及桌面1366px/手机390px的清空和开始确认、取消、失败阻止启动、分页归零、停止不清空和断开本机的支付提示。所有界面验收使用合成接口，不发送招聘消息或创建真实支付订单。
