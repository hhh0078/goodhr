# 自动回复灰度与顶栏显示

## 当前公开状态

自动回复尚未开放。所有账号（包括管理员）的新开启动作统一提示“功能灰度测试中，暂不开放”。工作台仍可查看待确认和运行状态，历史、已有资料编辑与关闭沿用原权限；不因灰度把用户引导去购买更高套餐。

前端 `lib/auto-reply-rollout.ts` 的 `AUTO_REPLY_ROLLOUT_CLOSED=true` 统一拦截顶部、面板、岗位开关和设置弹框；原启动、账号确认和重试流程源码保留，停止仍可操作。重试待办也先提示灰度，不先显示扣费确认。

服务端 `auto_reply_rollout.go` 的 `autoReplyPublicRolloutOpen=false` 是最终限制，不提供公开环境变量或账号名单绕过。`runtime/start`、`runtime/next`、`runtime/retry-reports` 和两个 Agent 岗位快照入口返回403及 `AUTO_REPLY_ROLLOUT_CLOSED`，不转入执行服务或调用模型。旧客户端收到 next 的终止错误后停止领取新命令；已执行动作仍须保存回执，不能直接清掉发送账本。

`runtime/stop`、`status`、`complete` 保留登录、账号和设备绑定核验，会员到期也可结束旧任务、提交已发生结果。套餐权益本身不变；未来开放后，执行入口仍按原规则核对Max资格。

岗位配置在原数据库行锁中判断关闭到开启的变化，并拒绝新开启；旧客户端缺少版本也无法竞态开启。已有 enabled=true 的配置保留原值，拥有原编辑资格的账号仍可修改正文或关闭；有效执行状态 enabled 则受灰度限制返回false。历史数据、聊天、附件、待确认审计与回执不删除。

重新开放时须通过代码发布同时调整前后端明确的发布常量，再复核启动、设备恢复、权限与发送防重。仅修改套餐或网页状态不能开放服务。

## 顶栏显示

会员胶囊移除套餐名和前置日历图标，保留实际剩余天数与AI余额；点击仍进入原订阅页面。未开通、已过期状态保持原提示。

只调整顶栏显示：余额大于1元时显示原金额的整数部分，不四舍五入；1元及以下保留接口原精度，缺失时沿用0.00。实际余额、AI扣费、订单与账单精度不变。

| 接口余额 | 顶部显示 |
| --- | --- |
| 100.9999 | ￥100 |
| 1.0001 | ￥1 |
| 1.0000 | ￥1.0000 |
| 0.1234 | ￥0.1234 |
| 0.0000 | ￥0.0000 |

本地程序连接胶囊只显示版本号，移除端口文字；连接状态、刷新连接及内部地址选择保持原逻辑，诊断页面必要的端口信息不受影响。

## 本次验证

2026年11月9日在隔离测试环境验证，未部署生产：

- 后端全模块真实 PostgreSQL 测试通过（84.833秒），五组灰度专项 race 测试通过（2.583秒），`go vet` 通过。
- 前端154项单测、38项相关界面用例通过；覆盖普通用户、管理员、未开会员、离线、旧配置维护、停止、余额边界及390px手机布局。TypeScript与生产构建通过。
- 真实登录页面已验证：启动提示灰度、原配置正文可查看、未保存的关闭后再开启被拦截；会员页面同步显示灰度限制，顶部显示“剩5天 · AI余额 ￥100”，本地程序只显示版本。
- 隔离后端五个执行入口均返回403；旧设备启动请求在外围返回502并带相同灰度文案，执行前的岗位快照403使其无法启动。测试前后运行18条、指令16233条、聊天39条、发送22条均未增加。
- 原配置 `configured_enabled=true` 和套餐 `allow_auto_reply=true` 保持不变，有效执行状态 `enabled=false`，确认灰度拦截未改写用户配置或付费权益。

合并最新开发分支时另发现故障回放的编号范围依赖数据库排序规则，部分语言环境会漏回放。该查询改用明确的 `COLLATE "C"` 比较与排序，保持固定前缀和20位序号的范围语义；不改变灰度边界或候选人数据。

完整后端、界面测试记录和页面截图保留在本机本次隔离验收目录，不加入源码仓库。
