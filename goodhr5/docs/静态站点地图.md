# 静态站点地图

用户于2026-11-20要求沿用GoodChat已验证的静态响应方向，默认地址继续为 `https://goodhr.58it.cn/sitemap.xml`，并自动纳入新文章。GoodChat的静态路径在Bing成功读取，只能证明该方案有效，不能据此断言原故障必然由分块传输或某个响应头导致。

## 原有规则与数据来源

Next原动态地图路由继续作为本机生成源，不改公开文章查询、分页大小、canonical、lastmod、语言标记或robots规则。生成器通过 `http://127.0.0.1:5175` 读取原XML，绕过Nginx对外的静态路径，避免刷新旧静态副本形成循环。

小站保持原urlset；文章超过原阈值时完整复制sitemapindex及每个分片。任何读取失败、错误HTML、非法XML、未知分片、重复链接或非canonical/非公开地址都会停止本轮更新，保留上次完整版本，不把错误当作“所有文章已删除”。文件逐字节保留，不重写原文、日期或语言声明。

## 自动更新

原 `auto_deploy.sh` 每分钟先调用 `scripts/refresh_public_sitemap.py`，再继续原Git及自动发布流程。地图有独立锁，因此长时间镜像构建、发布锁占用或Git同步失败不会阻止文章目录刷新。无需新增宝塔任务或重新发布应用。正常情况下文章发布、撤回、删除及定时公开变化在下一轮刷新体现；上游持续失败时会保留最后完整文件并在 `deploy.log` 告警，不能声称失败期间内容仍实时。

输出只在 `/www/wwwroot/goodhr-production/seo-static`：先完整写入新一代XML，再原子切换 `current` 链接。内容相同不改mtime，不重复存档；成功切换后只移除上一代本脚本拥有的公开XML缓存，不触碰数据库、上传、发布备份或其他目录。

生成成功后调用 `scripts/install_static_sitemap.py` 自动接入Nginx。它必须确认唯一的 `goodhr.58it.cn` server及原5175/8086代理目标，先保存配置原文到 `/opt/goodhr-release/sitemap-config-backups/<SHA256>.conf`，再只替换地图专用规则。共享正则、robots、SSL、域名和业务代理保持原样。原配置、变更后配置均需通过真实 `nginx -t`，失败恢复原文；成功才平滑重载。规则不变时不重载、不重复备份。已有配置与源码不符、外部并发修改或无法确认目标时停止，不猜测覆盖。

Nginx使用项目内 `nginx.sitemap-static.conf` 的精确 `/sitemap.xml` 和更具体的 `/sitemaps/` 前缀读文件。关闭这些路径的动态gzip和文件描述符缓存，使GET/HEAD返回正确长度，并在切换快照后读取新文件；使用 `expires -1` 生成no-cache，避免通过location级add_header破坏父级HSTS等头部继承。参考：[Nginx headers](https://nginx.org/en/docs/http/ngx_http_headers_module.html)、[Nginx location](https://nginx.org/en/docs/http/ngx_http_core_module.html#location)。

## 验证与恢复

- 本地测试：`python3 -m unittest discover -s scripts -p 'test_refresh_public_sitemap.py'`、`test_install_static_sitemap.py` 和既有 `test_auto_release.py`。
- 如本机已有官方Nginx镜像，可显式运行 `GOODHR_SITEMAP_NGINX_TEST_IMAGE=nginx:1.24-alpine python3 -m unittest discover -s scripts -p 'test_static_sitemap_nginx.py'`。测试不拉取镜像、不开放主机端口，仅创建并结束本轮测试容器。
- 线上验证普通请求及搜索引擎UA的GET/HEAD、XML解析、Content-Length、分片和robots；实际Google/Bing是否读取成功，仍以对应站长平台回执为准，不以本机200代替收录结果。
- 配置恢复使用本次SHA备份原文，经 `nginx -t` 后平滑重载；动态Next源一直保留。不要删除原配置备份，也不要通过改默认反代或停用自动发布绕过故障。
