# BOSS聊天裁切历史采集修复

本文记录2026-11-27反复点击同一候选人的实际页面原因，以及本地6.3.4.21的修复和验证。

在当前BOSS窗口复现的实际错误为“BOSS历史滚轮未到达消息区域，稍后再试”。浏览器视口1280×779，聊天消息容器顶边为-5.5px，第一条消息顶边也为-5.5px。整个聊天框上沿被窗口裁切，首条消息仍部分可见，历史实际已经到顶。旧判断要求消息顶边进入屏幕，因而即使两次真实滚轮均没有移动，也无法结束采集；未完成的持久采集意图下一轮又打开同一联系人。

本地 `internal/platform/boss/reply_messages.go` 增加仅针对这种裁切情况的几何核对。沿用Worker标准 `Find` 的边界框、两次真实滚轮、消息首尾不变三项证据。首条必须仍部分可见，并且顶边已经在真实聊天容器内；在容器上方、完全离屏、隐藏或缺少有效视口时均不判定历史完整。没有读取scrollTop、Vue或隐藏状态，也没有JS注入。

同一真实聊天修复前读到0条并报错，修复后完整读到5条，错误为空。排错工具只读取已打开的聊天，没有打开其他候选人、发送消息或改写业务数据库。工具验证完成后删除，只保留脱敏验收记录。四种几何场景的回归与BOSS平台原有测试通过。

Windows x64、macOS arm64和macOS amd64共用同一平台方法，未引入系统专属调用；需要分别验证Go编译。macOS安装包同时携带两种架构及对应Worker原生依赖，Apple芯片本机可独立目录启动验证。Windows安装及Intel真机运行仍需对应设备验收。

本轮云端工作台与日志使用主分支提交5b97c13a，经正式构建、隔离迁移及回退验收发布。此后发现的BOSS几何修复只合入dev并生成本地6.3.4.21安装包，不触发第二次云端发布，不上传客户端安装包、不更改公开下载或自动更新配置。原来的消息水位、已发送收据和未知发送保护保持不变。
