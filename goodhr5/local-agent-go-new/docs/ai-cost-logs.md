# 岗位 AI 费用日志

每次实际 AI 请求结束后，岗位日志新增一条费用记录，例如：

```text
AI 基础预分析，候选人“张女士”，本次消耗 ¥0.0023
AI 详情分析，候选人“张女士”，本次消耗 ¥0.0105
```

金额为本次内置 AI 调用实际扣除的人民币金额，精度为 0.0001 元。免费价格确实结算为零时显示 `¥0.0000`；缺少用量、连接中断、旧云端没有返回回执或扣费保存失败时，提示“本次 AI 金额暂未确认，可稍后核对余额明细”。自定义接口无法获取服务商账单时，提示“费用由服务商结算，暂无法获取金额”。不通过账号余额前后差额推算，避免多岗位或其他 AI 功能同时消费时串账。

## 覆盖范围与归属

- 主动打招呼：候选人基础预分析、文本或图片详情分析。
- 自动回复：每轮工具模型请求、简历整理、后台推荐报告。
- 临时错误重试按每个 HTTP 请求单独记录，不能用最后一次成功覆盖前面请求的费用状态。
- 评分可以提前返回，费用在完整响应结束后追加，不能为了显示费用阻塞提前评分。
- 任务、岗位、候选人与阶段在请求现场固定，不能使用当前页面候选人或动态岗位状态推断。后台推荐报告只有岗位归属，不伪造已结束任务的编号。
- 复用现有普通日志、复制、分享和上传链路，不新增费用表或修改扣费规则。上传费用摘要时移除候选人姓名；自动回复的正文仍留在本机。
- 历史日志没有对应的单次费用回执，不补造金额；本功能不提供累计金额。

## 云端与本地协议

本地在 OpenAI 兼容请求头设置 `X-GoodHR-Billing: 1`，云端支持此协议时返回同名响应头。普通 JSON 响应增加顶层 `goodhr_billing`；SSE 在上游完整结束并确认钱包写账后，先发送 `choices: []` 的费用分片，再发送唯一的 `[DONE]`。不请求回执的旧客户端保留原响应格式。

回执包含 `status`、`model`，只有 `status=charged` 才携带 `cost_units`。`cost_units` 为整数，1 单位等于 0.0001 元。`unavailable` 与 `failed` 均无确认金额，不能当作免费。金额来自同一模型配置下的既有钱包计费方法，只在写账成功后返回。

云端实现位于 `cloud/backend/internal/httpapi/ai_billing_receipt.go` 和 `ai_wallet.go`；本地读取位于 `internal/integration/ai/billing.go`，归属绑定位于 `internal/flow/shared/ai_billing.go`，显示与落库位于 `internal/flow/lifecycle/ai_billing_log.go`。

## 平台与验证

Windows x64、macOS arm64、macOS amd64 全部使用上述公共 Go 代码，没有系统专属调用或 Worker、OCR、浏览器操作变更。无需新增依赖或数据库迁移。

合成上游与真实本地 SQLite 测试覆盖四位小数、零金额、未知金额、JSON/SSE、工具请求、重试、提前评分后结算、并发归属、模型响应解析失败后的实际费用、钱包扣费失败及隐私摘要上传。验证不访问真实模型、不产生 AI 消费。

2026-11-07 验证：云端与本地 `go test ./...` 通过；云端 `go vet ./...` 通过；AI、共享流程、岗位生命周期、打招呼与自动回复包的 `go test -race` 通过；Windows amd64、macOS arm64 与 macOS amd64 均通过 `CGO_ENABLED=0 go build ./cmd/goodhr-local-agent`，并核对 PE / Mach-O 目标架构。

此次未发布云端或客户端安装包，实际使用需要同时更新云端回执服务和本地程序；Windows 与 Intel Mac 的真机安装、运行及真实付费调用未验证。Mac 本机验证为 Go 测试，未进行新版安装包安装或招聘网站实跑。
