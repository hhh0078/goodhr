# 自动回复思维文档

## 1. 文档用途

本文是自动回复功能的长期业务记忆。任何 AI 或开发者修改自动回复前，必须先阅读本文、`AGENTS.md` 和 `auto-reply-roadmap.md`。

这里记录可核对的产品决定，不保存 AI 隐藏思考过程。开发中发现的平台页面事实、失败案例和新风险，需要持续补充。

## 2. 一句话定义

自动回复是一条独立的本地候选人沟通主流程：本地 Go 负责页面编排、简历处理和 AI 工具调用，云端 Go 负责存储、权限、会员和邮件，平台动作只走现有 CloakBrowser 链路。

## 3. 已确认决定

| 编号 | 决定 |
| --- | --- |
| D-01 | 自动回复与主动打招呼是独立主流程，二者不互相调用。 |
| D-02 | 外层调度器允许两个流程安全穿插，同一时间只有一个浏览器动作执行者。 |
| D-03 | 打招呼每处理一位候选人前检查自动回复，单次最多处理3个未读会话。 |
| D-04 | 关闭自动回复后完成当前会话再停止，不中断原子步骤。 |
| D-05 | 平台由当前页面域名识别；平台页面事实必须实测，禁止猜选择器。 |
| D-06 | 对话页面可见的沟通岗位用于岗位归属；归属不唯一时不回复，只通知 HR。 |
| D-07 | 团队可以建立多份公司档案，岗位选择一份；成员可编辑，管理员可删除。 |
| D-08 | 岗位条件分为必须满足、需要确认、加分项。 |
| D-09 | 没有手机号时只保存临时会话和待完善资料，不进入正式简历库。 |
| D-10 | 团队内标准化手机号相同的候选人跨平台合并；平台候选人 ID 优先并分别保留。 |
| D-11 | 简历附件保存到云端 Docker 持久化目录，支持 PDF、DOC、DOCX、JPG、PNG，最大20MB。 |
| D-12 | 只有年龄时保存估算出生年份和精度，不能编造月份；性别非空时只能是男或女。 |
| D-13 | 自动回复模型必须支持标准 OpenAI `tool_calls`。 |
| D-14 | 单条新消息最多8次工具调用，工具参数最多修正2次。 |
| D-15 | AI 无法处理时邮件通知，但不暂停候选人；邮件包含岗位、候选人、性别和原因。 |
| D-16 | AI 可自动维护候选人确认项，只能建议修改岗位或公司资料。 |
| D-17 | 一条候选人新消息最多发送一条自动回复，不承诺未配置事实。 |
| D-18 | 首次最多同步5000条聊天，后续只做差量同步。 |
| D-19 | AI 审计保留180天；简历随候选人保存，删除候选人时级联删除。 |
| D-20 | 自动回复仅 Max 和全功能体验会员可用。 |
| D-21 | AI 工具、流程、简历清洗和校验在本地 Go；云端负责存储、权限和邮件。 |
| D-22 | 运行小窗显示 AI 总记录，普通页面步骤不能立即覆盖 AI 结果。 |
| D-23 | 第一条真实回归链路使用已经登录并已有岗位的猎聘企业端。 |
| D-24 | 简历结构化失败时只保留临时附件和会话，不把残缺数据写入正式简历库；下轮继续重试。 |
| D-25 | AI 返回空经历数组时不得清空已有资料；手机号、邮箱和微信都要先在本地校验，再交给云端二次校验。 |

## 4. 目录和调用边界

```text
Next.js 岗位页
  -> 云端 Go 保存配置、开关和业务数据
  -> 本地 Go 外层调度器
      -> greeting 独立主流程
      -> auto_reply 独立主流程
          -> internal/platform/{platform}/reply.go
          -> Go Browser Client
          -> TypeScript Browser Worker 封装能力
          -> CloakBrowser
```

自动回复主流程放在 `internal/flow/auto_reply/`。平台选择器只放各平台 `config.json`，平台动作只放对应 `reply.go`、`followup.go` 和 `detail.go`。公共聊天框、联系人侧边栏、真实滚轮、消息发送和下载监听必须复用现有能力，禁止复制四份。

## 5. 候选人确认项，而不是隐藏思维

产品中的“思维”使用结构化确认项表达：

- 类型：必须满足、需要确认、加分项。
- 状态：待确认、满足、不满足、不适用、冲突。
- 内容和稳定去重键。
- 来源：岗位条件、简历、聊天或 AI 新增。
- 证据消息或简历字段。
- 简短结论、创建来源和更新时间。

AI 可以自动增删改候选人确认项。AI 从聊天中学习到的岗位或公司信息，只能生成待审核建议，不能直接污染团队资料。

## 6. 会话和岗位归属

同一平台账号可能同时沟通多个岗位。不能因为某个岗位开启自动回复，就把整个未读列表都当成该岗位。

打开会话后按以下证据匹配：

1. 页面可见的当前沟通岗位。
2. 平台账号。
3. 平台候选人 ID。
4. GoodHR 已有岗位触达记录。
5. 获取不到稳定平台 ID 时，使用团队内标准化手机号作为后备身份。

仍然无法唯一匹配时不回复，只记录并通知 HR。猎聘企业端沟通岗位的位置、截断方式、完整文字和选择器必须使用现有 CloakBrowser 实测后记录。

## 7. 简历闭环

每个未读会话按顺序检查：

1. 云端是否有正式候选人和附件。
2. 聊天记录里是否已有候选人同意或发送的简历卡片。
3. 没有简历时复用平台索要简历能力，并发送岗位配置的话术。
4. 有卡片但云端没有附件时，打开候选人详情并下载。
5. 非 BOSS 平台读取在线简历并本地清洗、结构化，再下载附件。
6. BOSS 以附件 AI 结构化为主。
7. 在线简历没有联系方式时，再让 AI 从附件提取手机号、邮箱和微信。
8. 本地严格校验后上传云端。

正式简历要求手机号非空，但不限定11位。聊天可以先于简历存在，不能因为没有手机号丢失聊天。相同手机号跨平台合并时保留所有来源身份；关键字段冲突时保留证据，不能静默覆盖。

## 8. 聊天同步和发送保护

- 首次同步最多5000条，用真实滚轮加载历史；后续只同步差量。
- 消息优先用平台消息 ID 去重，取不到时使用方向、类型、正文、时间和顺序生成指纹。
- 每次点击会话前重新定位，打开后校验候选人和沟通岗位。
- 自动回复独立启动后，只打开一次联系人侧边栏；同一批未读候选人按列表顺序逐个点击处理，单个候选人处理完成后不关闭聊天框和联系人侧边栏。
- HR 手动消息作为最高可信的己方口径，但一次口误不能自动改公司资料。
- AI 生成回复后、发送前再次读取最新消息；出现新消息时废弃旧回复。
- 点击发送后必须回读确认；结果未知时先查，禁止直接重发。
- 一条候选人新消息最多发送一条自动回复。

## 9. AI 工具边界

第一版工具：

1. 查看岗位、公司、候选人和当前会话上下文。
2. 查看聊天记录。
3. 查看候选人简历。
4. 查看候选人确认项。
5. 新增或修改候选人确认项。
6. 索要简历。
7. 发送消息。
8. 提交岗位或公司资料修改建议。
9. 通知 HR。

发现未读、打开侧边栏、差量同步、下载保存附件、手机号合并、权限校验和发送回读属于固定流程，不交给 AI 决定。

AI 只回答本次招聘相关问题。身份不唯一、岗位不唯一、资料冲突或缺少可靠答案时，不猜测、不发送，改为通知 HR。

## 10. AI 审计和运行小窗

每次 AI 运行使用统一 `trace_id`，云端保存：

- 发给 AI 的消息。
- AI 流式内容和完整返回。
- 工具名称、参数、校验结果、执行结果和耗时。
- 实际发送内容和页面回读结果。
- 错误、修正次数和邮件结果。

运行小窗主区域展示当前候选人的 AI 总记录：聊天或简历同步中、AI 请求转圈、候选人问题、工具调用摘要、最终回复或无法处理原因。最终结果必须保留几秒，普通点击日志不能马上覆盖。

## 11. 通知规则

无法处理邮件至少包含：

- 岗位名称；无法确定时写“暂时没认出来”。
- 候选人名称。
- 性别；未知时写“暂时没看到”。
- 平台和最新消息摘要。
- 无法处理原因和建议动作。

同一候选人、同一消息、同一原因只发一次。发邮件不会暂停候选人，后续新消息仍允许重新判断。

2026-08-04 已使用猎聘企业 Profile 和“高中数学老师”岗位处理候选人“邓云川”。页面岗位唯一匹配、聊天历史差量同步、缺简历时索要简历、默认文字发送、发送后回读和云端会话落库均通过。猎聘“未读”标签会保留 30 天前旧记录，但悬浮入口只提示当前新消息，因此每轮只能按入口数字处理；没有入口数字时安静等待，不能把旧未读当成新消息。当前候选人尚未提供简历，AI 工具调用、AI 审计和人工通知应在后续真实消息满足条件后继续验证，不能提前伪造通过。

2026-08-06 再次使用猎聘企业 Profile 实测“王先生”简历卡片：附件预览、237805 字节 PDF 下载落盘、在线简历同页浮层 3218 字读取和关闭校验均通过。猎聘关闭在线简历浮层时会同时关闭聊天框和联系人侧栏，因此平台流程固定先处理附件、最后读取在线简历。候选人小程序当次发送的多条消息虽显示“送达”，但没有进入当前企业账号的联系人列表或聊天记录，且会话页面岗位为“校区负责人/招生主管”、当前开启自动回复的岗位为“高中数学老师”；本轮未伪造未读，当前用户云端仍为 0 份正式简历、0 个附件、0 条自动回复会话和 0 次 AI 运行。

## 13. 长期风险

- 页面改版导致身份或岗位读错比选择器找不到更危险，必须坚持“不能唯一就不发”。
- 姓名不是稳定身份，同名候选人不能合并。
- AI 模型可能声称支持工具但返回格式不稳定，需要启动探测和运行时错误策略。
- 聊天和简历属于敏感数据，普通运行日志必须脱敏，删除候选人必须级联文件。
- 两个流程抢浏览器会串页面，必须由唯一调度器串行化。
