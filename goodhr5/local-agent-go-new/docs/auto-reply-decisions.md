# 自动回复实现约定

本文件描述当前 `dev` 的实现。旧分支中云端保存聊天原件、云端调用结构化与推荐 AI 的做法已被替换，历史测试不能作为当前版本已在招聘平台发送成功的证明。

## 数据和职责

- 本地 Go 负责消息轮询、候选人身份核对、AI 工具循环、简历结构化、条件确认和推荐报告生成。
- TypeScript Worker 只提供标准浏览器动作，不包含 AI、数据库或招聘平台业务。
- 页面读取和操作只用标准 Page、Locator、鼠标、键盘、真实滚轮和截图，禁止脚本注入。
- 云端保存公司档案、岗位配置、权限、摘要和人工协助通知。
- 完整聊天、候选人原文、原始附件、AI 输入输出和工具结果只保存在本机。自动回复开关本身不构成上传这些数据的授权。
- 只有岗位明确开启 `output_structured_resume`，才在后台同步结构化简历及本地生成的结构化推荐报告；不上传简历原文、聊天全文、截图或附件。服务端独立校验开关和归属。
- 本地全局日志保留必要详情，云端岗位日志只接收自动回复摘要。

## 猎聘联系人与附件下载

猎聘企业端统一从「全部」联系人发现消息。如果用户留在别的标签，进入时选一次「全部」；后续轮询保持当前标签。每轮读取已渲染行的稳定会话编号和可见变化，只对变化行补读详情。跨窗口读取核对重叠行。红点消失、没有红点的联系人都可以进入核对；已打开的聊天直接比对最新消息编号。

本机按登录用户、平台、招聘账号和任务限定范围保存列表摘要与待核对状态。初次看到旧联系人时建立基线，已有聊天从上次保存的消息继续。后来才出现的行或摘要发生变化的行按消息时间与已存编号核验。首次采集没有旧消息编号时，同一分钟的时间本身无法证明先后，需比对本轮实际改变的可见预览。对列表中已有可靠消息编号的联系人，按上次核对时间轮查，每轮最多增加一人。列表一直有新消息时仍定期给最久未核的人一个名额，防止同一分钟同文让预览看起来没变。删除后的重新联系沿用更严格的删除时间边界。

已经沟通过的候选人只发猎聘标准投递卡时，直接回复一次简短签收；卡片含自由留言、提问或同时发来文字时走正常问答。已确认的岗位条件不再夹进签收消息。候选人收到签收回复后，程序优先在当前聊天处理到期的附件。普通多人任务会轮流检查其他会话。点击前从可见简历卡核对候选人和来源，在本机原有的下载监听中登记页面与文件。预览和下载使用不同临时签名时仍需核对文件主机、路径及其余身份参数。监听把同一下载的完成记录交给自动回复，手动下载继续进入原导入流程。已开始下载的大文件可等到本次采集的截止时间。下载按钮点击前登记现有标签，监听新标签与主页面导航。取得保存回执后，按完整文件路径确认唯一匹配页，只收起本次新增的文件页。已有同一路径的文件页予以保留；如果浏览器只有它和原招聘页，恢复招聘页到前台。

Windows x64、macOS Intel 和 Apple Silicon 共用上述 Go 流程、Worker 的标准定位和原生下载记录。三个目标均需执行编译检查；开发机上的双方聊天、下载与真实点击验证覆盖 Apple Silicon。

## 存储和恢复

- SQLite 按账号隔离候选人、平台身份、会话、消息、条件、附件、模型运行、发送回执、同步待办和报告。每条业务实体有独立标识与版本，消息可按会话和处理状态查询。旧版设置快照经校验后迁入实体表。
- 附件先检查大小和 SHA-256，再复制到本机私有目录。原下载临时文件清理后，持久附件仍可恢复。
- 会话按平台、账号和稳定会话编号保存；平台身份与标准手机号只在明确匹配时关联。
- 首次聊天最多保留5000条，之后按稳定消息键差量保存，重复同步不重复插入。
- AI 审计按完整运行裁剪，运行和工具记录均控制在最近1000条以内，避免孤立引用。候选人和条件资料不随审计裁剪删除。
- 本地存储缺失、损坏或写入失败时返回明确错误，绝不回退云端保存全文。

## 删除后本机如何收尾

Agent 核实当前账号后，按云简历编号找到本地候选人。首次上传尚未确认时，可以使用同账号下唯一的稳定平台来源。来源在不同招聘账号间存在歧义时，只清理已经直接关联云编号的记录。后台收到已删除的上传回执，也会丢弃旧写入。

逐条删除的范围包括本机结构化候选人、关联会话、消息与发送收据、确认项、AI运行及工具记录、报告、同步待办和旧账号快照中的相应条目。清理会保留无原文的稳定编号标记，防止正在运行的旧任务把资料写回来。

受管附件按账号目录和SHA-256命名。文件回收单独复核相对路径、符号链接、内容摘要及剩余引用。用户下载原件保持在下载目录。macOS arm64、macOS amd64 和 Windows amd64 共用 Go `os.Root` 的私有目录约束。Windows文件仍被其他程序占用时会保留清理意图，稍后只重试这份简历。回归见 `internal/integration/cloud/auto_reply_purge_test.go`。

### 删除后同一候选人重新联系

在猎聘，同一招聘账号、会话和候选人均核实后，程序只采集平台时间晚于本次删除的消息。读取先从聊天底部开始，到达删除时间或已处理的消息便停止；若时间不清楚，不据此建档。猎聘只显示到分钟，删除当分钟内的消息不能证明先后。旧版事件没有删除时间的，以升级时记录的保守时间为准。

新收到的候选人消息可以重新开启对话并使用岗位已有的确认条件；生成正式简历还需要新发的附件，必须核对该条入站卡片并拿到对应文件。过去的简历、回答和附件不带入。每次删除保留不含原文的来源摘要和序号，迟到的旧上传和旧报告不能覆盖新档。未入库的草稿和下载副本按附件、正文及候选人身份核实，历史事件证据不足时可在导入窗口逐份移除。上述判断使用三个目标系统共用的 Go 逻辑。

macOS 两种架构与 Windows x64 的受管 Camoufox 使用相同的原生下载设置：文件下载完成后不自动弹出下载面板，保留下载管理和用户手动打开面板的能力。Worker 需要把聊天末条滚入可见区域时，在聊天容器的可见中部发送真实滚轮，以消息相对容器的位移判断进展；换落点仍无进展则停止，并保留采集待办。对应回归见 Worker 的 native-downloads 和 list-window-progress 测试。

## 浏览器与回复

- 主动打招呼和自动回复保持独立，由外层调度器在候选人安全边界串行运行，同一时刻只有一个浏览器动作执行者。
- 岗位归属、候选人身份或当前聊天框不能唯一确认时，不发送消息。
- AI 工具每轮最多调用 8 次，参数或协议最多修正 2 次。本轮待处理消息合并输入一次，近期历史保留正文、消息类型、方向、平台时间及可核对的来源键。本机完整记录用于审计。
- 猎聘发消息时先核对原页面、候选人、岗位、最新消息、输入焦点和完整草稿，再按一次 Enter。必须回读到新的己方气泡才登记成功。气泡延迟时短暂复查，如果候选人抢先发来另一条，则在最新窗口里核对原消息编号与新气泡的先后。只有确定按键没有触发发送时，才复核后点发送按钮一次。网络超时或不确定是否已送达时保留发送记录等待核实。
- 猎聘关闭会话或附件预览时，先核对原页面和相应弹层，按一次 Esc 后检查。仍显示原弹层才复核并点击其关闭按钮。其他平台接入、测试和回退的共用约定见 [本地开发规范](../AGENTS.md#聊天快捷键与备用按钮)。
- 每条候选人消息最多准备两条回复：先回答，再单独询问一个尚未确认的必要条件；两条之间出现新消息则取消第二条。
- 自动回复保持当前聊天游标，并检查已被平台标为已读但仍有新内容的会话。
- 企业已有明确岗位地点时，只答候选人实际问到、资料能够核对的部分。草稿把未知事项写成正在办理或承诺之后联系时，需纠正后再发；全部问题都缺少可靠依据则转人工。
- 人工协助通知只向云端发送显示名、岗位、平台及原因编号摘要；完整原因和消息留在本机。

## 简历与推荐

- 复用现有本地 TXT、DOC、DOCX、PDF 和图片提取器，扫描件使用本地 OCR；复用本地 `ParseResume` 生成结构化资料。
- 本地附件保存上限20MB；当前共用文件解析器上限10MB、PDF最多20页，超出时明确报错并保留本地文件供人工处理。
- AI 字段必须校验，空经历不能清掉已保存资料，缺少有效手机号时不进入正式候选人状态。
- 条件由 HR 在岗位设置中启用。AI 只能依据聊天或简历更新已有条件的状态；岗位名称、职责及候选人的自述不能自动变为新门槛。推荐逐项核对当前启用的必要条件和确认条件，缺项或证据不足就等待。旧版 AI 自建的条件保留历史记录，不用于追问或推荐；未配置必要条件或确认条件的岗位不生成报告。
- 推荐任务以业务输入摘要去重，领取有五分钟租约，生成最多尝试三次，报告先在本机落盘。
- 报告生成不会阻塞消息发送。云端关联尚未准备好或上传失败时，本地报告保留，后续轮次复用报告重试发布，不重复调用 AI。
- 公开报告只展示已经授权同步的结构化结果，不提供本地聊天全文。

## 验证范围

2026 年 11 月 7 日，使用隔离后台、macOS 本地程序、已登录的猎聘企业端和候选人小程序进行了真实收发。8 条测试输入覆盖岗位问答、无依据问题转人工、条件更正与恢复、两条连续提问合并回复。验收还核对了真实 PDF 附件、历史重采与增量、简历合并、来源岗位和私有报告预览。接管通知走隔离环境的开发邮件通道。

一次单问从候选人发送到企业端确认回复用时 58.7 秒。一次双问从最后一条发送到确认回复用时 41.3 秒。模型分别用时 1.5 秒与 1.8 秒，主要时间花在未读列表、读取会话及真实输入操作。样本只覆盖本次会话、机器和模型。

回归测试另覆盖无附件、账号隔离、重复消息、旧库恢复和发送结果不明。其他招聘平台及 Windows、Intel Mac 的真实收发未在本次验收。

2026 年 11 月 8 日在 Apple Silicon 上复测猎聘企业端。收起聊天、留在「全部」时，从小程序发送城市问题到企业端确认回复用时 18.168 秒，旧流程同口径为 57.053 秒。新流程扫描列表 0.985 秒，Enter 0.188 秒，详细读取最近 8 条消息，未上翻、未切标签。已开聊样本为 11.822 秒。两条同分钟同文在真实聊天中分别留下两个入站编号并合并为一个回复。纯简历投递实测从点击投递到固定签收 7.437 秒、到私有文件关联 20.063 秒、到推荐报告发布 72.802 秒。附件预览用一次 Esc 收起，未点击关闭。另一次投递中，原生下载落盘后又等了 337 毫秒才观察到新文件页。收起该页和猎聘预览后，macOS 前台仅剩原招聘标签。单次数据受轮询开始时点、回复长度及模型响应影响。
