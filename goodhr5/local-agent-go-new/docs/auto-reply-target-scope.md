# 自动回复单会话限制

临时验证时可限制 Agent 只处理一个指定候选人的会话。未配置限制时，正常自动回复行为保持不变。

启动 Agent 前设置 `GOODHR_AUTO_REPLY_TARGET_JSON`，内容为：

```json
{
  "candidate_name": "平台显示的完整姓名",
  "platform_thread_id": "平台稳定会话编号",
  "platform_candidate_id": "平台稳定候选人编号"
}
```

三个字段均必填，不接受仅姓名或本机推测的会话编号。普通前端点击开始即可；统一 preflight 会把进程限制补入请求。请求不得覆盖为另一候选人或会话。配置无效时拒绝启动，不会退化为无限制模式。也可在单次自动回复启动请求中传同结构的 `auto_reply_target`，进程已设置限制时两者必须完全相同。

当前猎聘企业端实现实时身份验证：会话编号复用联系人配置 `thread_meta` 中的 `to_imid`，候选人编号复用当前聊天框按钮配置 `message.candidate_id_source` 中的 `cid`。只通过现有标准读取接口获得，不注入页面脚本，不从历史消息推测当前身份。

- 未读扫描和本机待办恢复都按完整姓名、会话编号筛选；其他人的待办保持原样。
- 打开联系人时，以刚读取的完整平台属性限定点击目标，避免列表重排导致按旧序号点错人。
- 打开后先核对实时候选人编号，再读取历史；读取、简历操作和每次发送前继续复核。
- 姓名相同但编号不同、编号读不到或页面切到别人时，拒绝动作。正常页面读取也无法证明身份时，需要人工核对，不放宽限制。
- 尚未实现实时身份核验能力的平台拒绝启用限制模式；不会只靠姓名运行。

实时核验能力定义在 `model.AutoReplyIdentityVerifier`。任务生命周期的 `newLoggedRuntime` 日志包装按底层真实能力保留该接口，同时保留原有详情浏览能力；不支持核验的平台不会被包装成支持。组装回归使用正式 `platform.RuntimeFor("liepin")`、日志包装与 `auto_reply.Flow.Run`，并验证包装后的同名不同 `cid` 仍被拒绝，避免仅直接测试裸平台对象而漏掉实际任务入口。

限制使用跨平台 Go 类型与环境变量，平台身份读取放在 `internal/platform/liepin/reply_identity.go`；没有系统专属调用或新的 Worker 通道。已验证 Windows amd64、macOS arm64、macOS amd64 编译及守卫单元测试、race 检查。编译与合成测试不代表真实平台发送或其他操作系统安装已验收。

## 历史消息标识升级

猎聘配置 `behavior.auto_reply_message_identity_version=1`，本机会话缺省版本为 0。任务启动首次取得已开启岗位时，只对当前登录用户、招聘账号、已开启岗位及单会话限制内的已有会话，复用 `CaptureIntent` 登记一次完整重采；轮询不反复扫描账号历史，运行中新增开启岗位下次启动再登记。历史读取不传旧增量锚点，必须按既有真实滚轮规则确认到顶；5000 条截尾、取消、读取失败或与旧消息无交集都不能升级版本。没有任何旧消息的空会话保留正常空同步，不升级也不登记重采。

完整消息沿用现有同步事务，旧锚点之前缺少的重复消息标为 `history_backfill`，不新增待答、不改变已有发送凭据。版本与采集完成同事务保存，成功后回到增量读取；简历采集内部的来源核验不承担历史迁移。该机制使用同一份跨平台 Go 实现，无新增 Worker 能力或系统分支；回归覆盖 87 条补到 89 条、账号岗位限制、失败不升级以及完成后轮询和重启不重复全读。
