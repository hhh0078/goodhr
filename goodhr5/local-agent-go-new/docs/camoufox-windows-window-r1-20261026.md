# Windows Camoufox 窗口刷新修补

2026-10-26，用户补充要求 Windows 也更新。本次沿用 Mac 已验证的上游 [PR #861](https://github.com/daijro/camoufox/pull/861)，给现有 `152.0.4-beta.30` 加入浏览器内部窗口刷新设置。官方 158 与当前客户端原生下载通道不兼容，因此不直接切换全局版本。

实际功能改动为 `TargetRegistry.js` 打开浏览器窗口时设置 `domWindow.browsingContext.forceAppWindowActive = true`。招聘流程、AI 逻辑和正式 Go/Worker 源码没有修改；新增源码只负责隔离测试、候选打包和原生 Windows 验收。没有访问招聘网站或向网页注入脚本。

## 验收计划

1. 固定当前公开 Windows 原包：`camoufox-152.0.4-beta.30-win.x86_64.zip`，493141328 字节，SHA-256 `ea52a02fb1cfb1813ef6a326bea03fb2b650c9774143d953a94a27bfc8f10072`。
2. 原包与候选在独立 `camoufox-upgrade` 目录展开，各自用真正 Windows Go 资源安装方法准备 v12、原生下载、中文包和 UBO；不在 Mac 上把 Windows 目录当成原生验收。
3. 使用 GitHub Windows 原生虚拟机、Node 22.19.0、锁定的 Worker 依赖，有窗口运行。旧版已完成三个公开页面、三次全新会话、每站三十轮输入；修正清理夹具后用三会话九轮补验关闭。候选仍完整运行三会话、三站各三十轮，每次首站额外真实遮挡六十秒。每轮用 Locator 边界确认两次真实滚轮确实移动正文。
4. 候选另用正式 ActionService 验证启动、遮挡前滚动、真实窗口遮挡、遮挡后滚动及正常关闭。PowerShell 夹具只查指定测试 PID 的可见窗口边界，不读标题，不激活应用，不截获鼠标，定时自动退出。
5. 独立核对双层 ZIP 的成员、元数据、权限和内容，只允许根 `omni.ja` 内的唯一窗口管理资源改变；42 个 Windows EXE/DLL 必须完全一致。
6. 发布采用原生 Windows 作业生成并实际安装测试的精确 ZIP。不同系统的压缩字节可能不同，不能用 Mac 重压缩的同名包替代。CI 完整门槛通过后再经 MCP 上传、全量核验服务器与公网下载，并仅更新 `runtime_components.camoufox.win`。

- 修补资源在原生适配前的 SHA-256 必须为 `d41ff340529a47f3da99bba20892ad5f3ce95fee51da5c0929d8bc818645993b`，与两架构 Mac 使用同一功能修复。
- 首轮原生作业 [40322148358](https://github.com/hhh0078/goodhr/actions/runs/40322148358) 通过 PS1/C# 自检、双层 ZIP 审计和两份浏览器的 Go 适配，但在安装 `better-sqlite3` 时遇到 node-gyp 不识别 VS18。该轮没有运行浏览器滚动，不作为通过证据。

- 已修正空清理列表，并在已证明属于测试进程树的候选中按真实可见窗口确认唯一主 PID；仍复核启动时间、执行路径和父 PID。`continue-on-error` 仅用于保留对照结果，发布时同时核验原始 outcome、完整长测 JSON 和正式 Worker JSON，不能把步骤 conclusion 当成验收通过。
- Windows 原生测试机屏幕为 1024×768，浏览器窗口为 1280×900；WinForms 遮挡窗被系统尺寸限制为 1044×788。只读诊断证实它已可见、API 全成功且覆盖全部屏内浏览器，旧的完整屏外边界相等判据误拒绝了夹具。现按浏览器与虚拟屏幕交集设置目标，并严格要求不透明实际窗口完整包含该交集；少覆盖一像素也失败。保留原始、屏幕、交集和实际坐标，没有通过去掉遮挡验收获得通过。
- 官方 GitHub Windows 资产摘要和大小与当前 oss2 原包完全一致，后续直接从该官方地址取固定原包，保持 SHA-256 校验。Python 3.12 原生 Windows 生成的候选摘要与本机同名包完全相同；只有实际成功作业的摘要一致时才可使用本机相同字节，不能仅凭文件名替换。
- 测试工具补充 Windows 支持后，Mac 三站各一轮、六次滚轮并含真实遮挡回归通过，滚轮最大 13ms。Mac 正式 Worker 遮挡滚轮 2425ms 完成，正常关闭，精确进程检查没有本次浏览器或夹具残留。

## 使用方式

验收并发布后，刷新后台“组件信息”，点击“更新运行组件”。更新完成后完全退出 Camoufox 和 GoodHR 本地程序再重新打开，使 Worker 加载新组件目录。版本号保持真实的 152，但安装器会比较 SHA-256，因此同版本的新修补包仍会重新安装。

当前安装流程会更新后续 Worker 的环境变量，已有 Worker 仍持有原进程环境；因此只关浏览器窗口不足以确保选中新目录。本次通过使用指引解决切换，不扩大范围修改本地程序的安装流程。
