# 候选人列表加载修复（6.3.4.5）

2026-11-17。诊断中的 Windows 6.3.4.2 在 13:42:36 跳过本批最后一位候选人，13:44:35 报错。此前连续 51 位人选被基础筛选跳过，这条路径不会滚动。下一批推进执行了 16 轮滚动，到约 108 秒时平台已从 300 张卡片增加到 350 张，但在两分钟总预算内完整读取下一批 20 人时只剩约 11 秒，最终超时。这不能解释为平台完全没有加载新人。

## 实现位置

- `internal/platform/common/candidate_scroll.go`：保留已有真实滚轮追赶本批末尾的修复；等待追加时复用现有 `FindAll` 的 `ProbeOnly`，从 `nextIndex` 只探测一张卡片，不读姓名、正文或其他字段。发现新人就推进游标，由主流程下一批调用 `FindCandidates` 完整读取并核对身份。
- 保留首卡身份比较，虚拟列表替换旧行后从零读取；保留到底等待、滚动无进展、取消和错误传递。没有延长固定超时，没有把加载失败视为没有更多人。
- BOSS、前程无忧及其他无限滚动平台复用同一公共能力；翻页入口保持原流程。Worker 复用已有协议与标准 Locator，不新增平台逻辑或页面脚本注入。
- `internal/flow/greeting/flow.go` 同时保留上一版 Mac 已发布的修复：确认聊天后先发首次招呼语，再索要资料，避免邀投递失败吞掉首次消息。

## 验证

- Go 回归覆盖连续跳过后追赶末尾、下一批已加载、滚动后追加、慢页面不重复完整读取、进入下一批后资料完整、跨批同名、虚拟列表替换、网络延迟、到底稳定、浏览器错误、取消及断点恢复。
- Worker 既有探测与滚动进度测试 25 项通过；探测返回空字段，不生成无用元素引用。
- 三种目标共用 Go 公共代码和原有 Worker，没有新增系统专属调用。编译检查覆盖 Windows amd64、macOS arm64 和 macOS amd64；Mac 安装包同时包含 Apple 与 Intel 主程序和各自原生依赖。安装包发布证据另见对应发布记录。
- 版本沿用第四段补丁号 6.3.4.5；按现有前端版本策略，6.3.4 至 6.3.4.4 升级均为可忽略更新，不改变更早基础版本的既有要求。
