# 候选人断点续跑与智联选岗

2026-11-11 用户确认：保存最后处理完成的候选人；再次开始优先找回位置，找不到则从头；覆盖全部平台及 Windows、Mac。当日用户登录前程无忧后补做真页验收。

## 断点行为

- 流程在当前岗位选择、筛选准备完毕后恢复进度。复用 SQLite `local_settings`，不新增数据库表，不改变自动回复的服务器归属。
- 设置键按 GoodHR 用户、平台、岗位、Profile 路径和显式账号标记隔离；页面完整 URL、岗位名称、筛选要求及发送选项以摘要核对，不把 Token、URL、姓名或简历正文保存到断点。
- 仅保存连续处理完成的前缀。只读取或预分析不算完成；有人未处理完，本轮后面的成功不会越过他推进断点。下次会重新检查这些未完成人选。
- 找回锚点后核对前面名单的顺序摘要。编号缺失、联合身份重复、前缀换序或配置变化时从头检查；真实读取失败、取消或断线继续报错，不冒充“找不到”。仅查当前已加载的公开名单，不自动改变筛选或为找锚点无限滚动。
- 保留一张已完成者用于尾部及分页判断，主流程根据完整断点排除这张重叠卡片，不把同名同龄但不同经历的人一起排除。分页成功后清零旧页行号，避免从新页中间读起。
- 断点保存在本机当前数据库；不跨设备同步，也不凭招聘网站同一 Profile 内未声明的换号猜测真实账号。

### BOSS真页补验

- 用户登录后，复用当前内置Camoufox和现有Worker，未改变岗位与筛选。正式名单方法读取首批3人，序列化第二人断点、重建平台运行时后恢复行号1；保留一张已完成者供主流程排除，下一人与原第三人一致。
- 仅在测试内存改为不存在的摘要，正式恢复方法返回未找到并清零游标；重新读取的首批3人逐个指纹一致。真实页面本轮覆盖平台定位与回退，跨运行SQLite持久化仍由流程存储测试和前程无忧真页测试覆盖，没有写入BOSS用户进度。
- 使用当前JSON数组和正式Go点击流程：基础信息外层行一次点击即打开真实详情；后续备用路径未重复点击。按正式AI图片详情能力生成2段长截图，人工查看画面可读；一次Escape关闭，未调用备用关闭按钮，且已复核弹窗消失。
- BOSS图片简历没有DOM正文，正式AI流程直接截图，不调用纯文字详情读取；不能将测试中的纯文字读空当作卡片未点击。此次当前布局实操通过，旧版和灰度路径兼容性继续由已有隔离回归覆盖，未声称在真页同时出现两种布局。
- 新增显式启用的 `TestBossDetailExistingPageLive`，复用配置选择器和既有浏览器链路，不发送招呼、不输入、不调用AI、不修改筛选、不注入脚本。真实发送和长期运行不在本轮验收范围内。

## 前程无忧读取超时

日志 [b230af4](https://goodhr.58it.cn/diagnostics/b230af4c3b983d316226b3106830d01901ad2a9f1f790dfc523c27e01d326a2e) 的 Windows 6.3.2 首次在从50张追加到100张后读取下一批耗满约43秒；随后重启从第0张读100张，读到约第43至47张附近再次超时。期间读取进度持续更新，不能称为浏览器完全卡死。

新增平台配置 `candidate_batch_size: 20`，仅限制候选人完整字段批次；`max_items: 100` 保留联系人和会话原有上限。公共头部探测仍只读1张，加载更多继续复用现有游标。未配置小批上限的其他平台保持原批量参数。

### 前程无忧真页补验

- 使用用户已登录、当前筛选不变的内置 Camoufox 与现有 Worker。正式 Go 名单方法从50张滚动追加到100张，核对100个不同候选人编号，没有重复或倒回开头；单次完整字段读取最多20人，最长约6.1秒（两轮实测）。
- 仅在临时 SQLite 测试库标记前20人已完成，真实滚到第20张附近后关闭并重开测试库、重建 Flow 和 Runtime；恢复游标为20，下一张公开编号与事先读取的第21张一致。向测试记录写入不存在的编号后，游标回到0并读回原首批20人。没有写入用户进度或替用户标记真实处理完成。
- 真页额外复现长距离定位的收尾边界：原30轮滚动耗尽后，目标距安全区仅数像素，继续真实滚轮即可到位。`job51/candidate.go` 仅在 Worker 明确返回 `SCROLL_FAILED`、步骤为 `scroll`、30轮确已用满、剩余距离已知且不超过48像素时，对同一精确目标额外补一段最多20轮；不递归重试，取消、断线、无进展或距离未知直接保留错误。卡片与实际按钮仍分别检查完整可见、固定页头和底部遮挡，不增加任何点击。
- 修复后重新从列表前部实操，先复现30轮耗尽，再自动收尾成功（约2.1秒），随后继续断点与100人读取验收。此次是真实滚轮边界复现，不等同于原 Windows 日志的整批读取超时。
- 新增显式启用的 `TestJob51ResumeSQLiteExistingWorkerLive`：只允许本机 Worker，拦截点击、输入与按键，超20人的字段请求直接拒绝。不会发送招呼、调用AI、修改筛选或改招聘页面DOM。生产原任务的AI与发送全链不属于这次只读验收。

## 智联偶发选岗

日志 [b32bf35](https://goodhr.58it.cn/diagnostics/b32bf35e3f012760535e0ea5ef34645598512d0b907d5d8f7eb77c58a66f9744) 的两次独立失败均是 `click_started=false`、原始原因“元素在操作前消失了”。

在用户已登录的内置 Camoufox 搜索页只读观察到：输入岗位后旧结果先保留，随后出现 `.jsn-job-selector-loading` 骨架并替换选项，再展示新结果。另观察到标题显示带省略号，而 `title` 属性保留完整岗位名称。

修复位于 `zhaopin/greet_job.go` 与本地 JSON：

1. 等可见加载骨架消失，并要求唯一同名目标连续稳定900ms。目标丢失或重新加载会重新计时，不是输入后固定睡眠。
2. 优先精确匹配完整 `title` 属性，旧页面没有该属性时仍支持完整显示文字。回读已选岗位也使用完整名称。
3. Worker 明确证明鼠标尚未按下时，最多再进行一次等待和重新定位；已按下、回执不确定、取消或断线不重复操作，不重新打招呼。
4. 已选岗位回显一致后才点确定，最终仍以同一卡片出现“继续沟通”为成功证据。

Go 的 `SelectorSpec.timeout_ms` 零值会省略，不能用零假装即时探测；新短探测显式使用1ms，避免缺失的旧版入口额外等待默认时限。

### 真实与隔离验收

- Mac arm64 的真实选岗弹窗中，正式新流程完整岗位选中1次、确定1次，平台未要求额外招呼语；同一候选人卡片随后显示“继续沟通”。没有联系其他候选人。此前旧逻辑的时序观察仅选择弹窗内岗位，没有提交招呼。
- 隔离本机页面使用真实现有 Worker、Camoufox、Locator、鼠标与键盘，复现“唯一岗位已找到，随后骨架出现、旧目标消失”的窗口。新流程等待加载和稳定后，选岗与确定均恰好一次，最终显示继续沟通。测试页面自己的 JavaScript 不是向招聘页面注入；结束后关闭测试标签并恢复原智联标签。
- Mac 真页多次旧点击尝试没有再次撞中 Windows 原日志中405/446ms的完全相同原生失败；实际观察和隔离复现的是加载空窗，不能冒充 Windows 设备复现。单元测试另覆盖明确未按下后重新定位，以及不确定结果禁止重试。
- 智联真实断点验收仅在测试内存模拟完成标记，序列化后重建平台运行时，恢复原位置及正确下一人；没有把合成进度写入用户数据库。真实跨运行 SQLite 持久化、未完成缺口、作用域及隐私由独立存储流程测试覆盖。

## 系统与发布范围

公共 Go 与本地配置同时用于 Windows amd64、Mac arm64、Mac amd64，没有新增系统专属调用或依赖。三目标编译与平台、流程、存储、协议测试通过；真实浏览器验收运行在 Mac arm64，不代表 Windows 或 Intel 真机已验证。

本次没有改 Worker、云端服务或正式数据库，也没有重打或替换现有安装包。配置通过 `go:embed` 随 Go 主程序发布，正在运行的旧程序不会自动获得本次改动；后续打包需使用包含本次提交的源码。
