# 6.2.0.3 详情框架与输入等待修复

Boss 现场日志显示详情 iframe 与推荐列表 iframe 并列挂在主页面。正文、截图和关闭按钮进入主页面的详情 iframe，弹窗是否已出现或已关闭则直接检查主页面 iframe 本身，不再依赖正文是否加载。

详情弹窗已出现但正文仍在加载时继续等待正文，不再重点击弹窗后面的卡片。打开检查失败后也清理已出现的弹窗：先尝试既有关闭按钮，再用 Escape；关闭后必须确认弹窗消失。清理无法确认时返回岗位停止错误，禁止在被遮挡的列表上继续处理后续候选人。

点击后的可见状态验证复用轻量探测，不读取目标坐标或启用状态。这样弹窗在检查途中移除时，不会因坐标读取进入默认三十秒等待，或用移除前缓存的可见状态误报关闭失败。

每次鼠标和滚轮协议调用在 Worker 侧最多等待 18 秒，给浏览器内部 15 秒保护留出回传诊断的时间；剩余请求预算更短时采用剩余时间。限时不依赖浏览器内部补丁，超时返回 `WORKER_UNRESPONSIVE`、隔离队列并触发旧浏览器回收，迟到的协议结果不能放行后续操作。

鼠标首尾和失败日志增加 `input.input_timeout_ms`、`output.input_wait`（来源、等待阶段、耗时与结果）。`input.native_input_patch` 和浏览器启动日志记录启动前磁盘资源检查的预期版本、安装版本、SHA256、位置与错误。磁盘检查与原生异常返回的运行中版本分别记录；`runtime_loaded_version=unconfirmed` 不会被解释为已验证运行中加载了该版本。

资源检查按实际可执行文件的位置寻找归档，兼容嵌套安装目录及 macOS 应用包；没有资源或修正失败时明确记录失败，不再静默跳过。平台选择器继续仅由本地配置提供。

验证覆盖正文与截图的并列 iframe 定位、正文缺失后的关闭、关闭后真实列表滚动、清理失败停止任务、Worker 独立限时和队列隔离，以及缺失/旧资源状态。真实浏览器使用本地静态页面和隔离浏览器故障模拟，未登录用户招聘账号。
