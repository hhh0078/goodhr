# 6.2.0.2 输入与详情诊断

本次针对刷新超时、详情检查失败和滚轮异常缓慢补齐证据。重要记录复用岗位日志上传和离线补传，不要求用户收集本地日志文件。

## 已修正

- 原生滚轮先订阅刷新完成通知，再请求刷新，避免同步通知丢失；刷新等待最多 5 秒。
- 原生鼠标和滚轮从激活阶段开始限制整次调用最多 15 秒。超时后拒绝迟到的回调；无法取消的调用触发队列隔离和浏览器回收。
- 详情打开检查只探测元素状态，不读取详情正文；空结果不会被当成打开成功。
- 浏览器关闭附带的历史鼠标错误不再成为本次故障的原生证据。
- 详细日志批量上传控制在 6 MiB 内，保留最新完整记录，避免超过云端 8 MiB 请求上限。通常仍保留最近 1000 条，超限时减少较旧记录。

## 分享日志中的证据

| 步骤 | 位置 | 排查内容 |
| --- | --- | --- |
| mouse_move/down/up/wheel | 出参.native_mouse | 原生失败阶段、激活/刷新/回执耗时、发送和确认次数、滚轮参数、窗口和选中标签页状态 |
| mouse_move/down/up/wheel | 入参.page_state、出参.page_state_after | 输入前后页面是否关闭、iframe 树、最近响应状态与网络失败 |
| click_target | 出参 | 实际目标选择器、各层数量、元素位置、标准 trial 点击检查的遮挡类别和遮挡元素结构 |
| click_landing | 出参 | 本次真实点击落点和目标显示区域 |
| click | 入参、出参 | 第几次尝试、是否配置结果验证、点击后标签页与 iframe 变化；未配置验证不代表详情已打开 |
| selector_probe | 入参、出参 | 完整定位层级、请求序号、匹配数量、属性/状态匹配数量、查询异常类型、重试次数和实际 iframe 树 |

`selector_probe.status=missing` 是预期探测结果，仍会上传。查询失败带 `query_error_type`，可区分真正零匹配、旧对象失效和页面关闭。trial 检查超时但没有明确遮挡证据时 `actionable=null`，不会被解释为必然不可点击。

页面事件最多保存最近 12 条，失败事件另外保留最近 8 条，避免正常后台请求挤掉错误证据。iframe 最多列出 12 个并保留总数及截断标记，标签页最多列出 6 个。页面快照控制在约 6 KB，超限时先减少正常事件和多余页面，再减少较旧失败；保留截断标记。网络记录只有地址、资源类型和状态，没有请求正文、响应正文或凭据。URL 移除账号密码、查询参数和锚点。

## 验证

- Worker 严格构建与回归测试，包含同步刷新、通知丢失、激活超时、迟到输入、历史误判、详情隐藏/缺失/查询异常及遮挡脱敏。
- Go 测试涵盖详情空结果、诊断请求参数、日志离线重试与大小限制。
- 真实 Camoufox 使用本地静态页验证正常点击、滚轮、双层 iframe 详情、遮挡和 HTTP 403。人工丢失刷新通知验证原生超时证据。
- 云端现有岗位日志覆盖、分享快照、脱敏和保留上限测试通过。

这些验证覆盖已确认缺陷和证据链，不代表已复现用户招聘账号中的具体触发条件。升级后应重新运行任务并生成新的分享链接；旧链接保存的是当时快照。
