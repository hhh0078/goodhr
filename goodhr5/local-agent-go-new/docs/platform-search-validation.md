# 招聘页面适配验收记录

验收日期：2026-11-02。源码基于 dev；未发布线上服务、未替换正式安装包、未执行生产数据库迁移。

## 本次范围

- 编辑岗位可切换平台，保留原岗位 ID、历史数据、统计和启停状态；按平台调整 DOM/OCR 详情模式。
- 新增智联搜索人才、前程无忧人才推荐及搜索人才；不增加页面选择项。
- URL 支持旧字符串、`{"url":"..."}` 对象及混合数组；选择器兼容旧对象及完整备用对象数组。
- 数组入口优先激活 Worker 当前识别的支持页，其次其它已开支持页，最后才打开默认地址。手动切换 Firefox 标签不保证同步 Worker 当前指针。
- 任务引擎未修改。旧单地址和旧对象选择器继续走原路径；新增前程代码由智联适配复制后逐项修改。

前程实测发现并修复了宽版 `long-btn`/窄版 `short-btn`、固定页头、底部客服和积分悬浮层遮挡，以及 DOM 编号包含列表序号等差异。按钮须通过真实滚轮进入上下安全区并完整露出；窗口太矮或有限校正失败时停止。每次操作按最新列表序号核验精确编号，不按同名、同龄或旧序号猜测。

一次搜索刷新使原人选离开当前名单，验收在点击前停止。另一次底部遮挡点开客服页，目标仍为未招呼且额度未扣；修复后先用拦截发送点击的真人定位验证确认两宽均安全，再完成单次实发。未自动重发。

## 智联搜索页沟通职位补充验证（2026-11-05）

- 启动搜索任务仍沿用用户的人才筛选，智联适配层只记录 GoodHR 岗位名。点击候选人卡片后，遇到「选择沟通职位」才使用弹框内的「职位名称 / 发布地」输入框。只确认唯一同名且选中后回显一致的职位。已预选职位时按平台实际路径直接招呼。
- 搜索页只点击一次候选人招呼按钮。需要选招呼语时沿用现有发送操作。只有该候选人的卡片显示「继续沟通」才记成功；找不到职位、重名、选中回显不符或未确认发送时停止并提示。
- 使用已有登录的智联搜索页和「小学数学教师」实发两条。原高级搜索页没有预选职位，程序搜索、选中、确认后同一卡片显示「继续沟通」。临时搜索标签先手动预选同一职位，程序只点击一次招呼，同一卡片直接显示「继续沟通」。临时标签已关闭，原高级搜索条件和缩放已恢复。
- 实发调用本次 Go 适配和已启动 Worker。验收入口为旧 Worker 展开既有搜索页选择器备用项，新增职位弹框选择器原样使用。合成用例同时覆盖找不到、重名、未确认、已沟通及旧推荐路径。Go 全套测试与 Windows x64、macOS Apple Silicon / Intel 编译通过；此次只交付源码。

## 前程搜索页按需选岗（2026-11-05）

- 搜索页启动只等待候选列表，不再依赖搜索框或岗位标题就绪；不自动选择搜索岗位、不填写关键词、不执行人才筛选动作。任务岗位名仅在 Go 中保存，供招呼后实际出现的职位选择层使用；推荐页原选岗流程保留。
- 候选招呼只点击一次，点击前和确认时均按平台稳定简历编号重新定位。实际出现原生 `.im-position-filter.position-filter-dialog` 时，才在该层的搜索框输入岗位检索词，精确核对唯一完整名称。原生选择层点中岗位后自动收起，没有额外确认按钮；必须等当前聊天的完整岗位回显一致，卡片也变为“继续聊聊”，才能记成功。
- 保留已打开职位层拒绝发送、重名及相似名称拒绝、异步回显等待、延迟弹框复核、取消和超时后不重发等保护。已识别的职位层无法核对时不作为已发送成功处理。
- 用户授权下在独立测试标签分别实发两次：有预选岗位和“不限岗位”各一次，均未自动出现职位选择层，同一稳定编号卡片显示“继续聊聊”。当前账号在“不限岗位”下会沿用上次沟通职位，不把这种情况写成“自动弹框已触发”。随后手动打开这次测试会话的原生职位层，使用正式 `selectGreetingJob` 成功搜索并选中“高级软件工程（半导体）”；真实回显数次仍为旧值，等待后核对目标名成功，没有重选或追加发送。
- 独立测试页的搜索条件由验收人员手动准备，与正式启动流程分开；搜索空页验证没有自动选岗、填词或招呼。页面定位使用标准 Locator 读取、鼠标、键盘及真实滚轮，没有脚本注入。测试中曾因下拉项处于滚动容器裁剪区而误开候选详情，未追加招呼；通过截图确认并真实滚轮露出选项后完成手动准备。测试标签已关闭，原标签保留。
- 招呼后自动出现该原生职位层的分支使用合成状态机回归；本次真实账号未自然触发这一分支。Windows、macOS Apple Silicon 和 Intel 共享同一平台 Go 代码与嵌入配置，不新增系统调用；交叉编译不代替 Mac 真机运行。
